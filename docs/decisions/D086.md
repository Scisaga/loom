**日期** 2026-08-27 · **状态** 生效 · **相关** §15.4、[D81](D081.md#d81--身份签名之后转述来的节点也能核对版本收窄-d73)

SSOT 里有 `components` 只证明“希望运行哪个版本”，不能证明节点已经安装，
更不能证明 Loom 会替外部包升级。此前模型注释和目标设计把三件事揉成一句
“进入同一收敛回路”，实现却只管理 Loom 自身二进制；这是典型的假生效。

当前先闭合最小可信链：renderer 只给实际运行该 workload 的节点下发期望版本；
report 对 sing-box 同时核 systemd MainPID 对应的运行 inode 与 unit `ExecStart`
明确指定的 `/usr/local/bin/sing-box` 磁盘文件（不能从 PATH 误认另一份），
对 WireGuard 的既有签名线名保持 `wireguard`（滚动兼容不能在 canonical v5 内
改名），语义明确是 `wireguard-tools` 包；固定执行 `/usr/bin/wg`，同时核对
`dpkg-query` 安装状态/包版本、关键配套文件归属和 `dpkg --verify`，数据面另由
握手证明。探测并行、限时、限制输出，并用短缓存 singleflight；缺失、读失败和不一致都使节点健康失败。
结果与 Agent 候选健康一样由节点签名，relay 只能转述，不能
把 mismatch 改绿。Agent 的 `component_version` 明确定义为状态线协议版本，
运行中二进制身份仍由 commit、binary SHA-256 与快照坐标证明。

外部组件的下载、校验、A/B 或包级回滚尚未实现，所以这一阶段只检测、不擅自
修复。没有 workload 启用真值的 Tailscale 版本直接拒绝；声明但尚未实现的
constraints、非 fail-closed fallback、凭据 expires_at 和多代秘密层也同样
fail closed。后续实现自动升级时，必须与真实 canary 和配置回滚一起进入事务，
不能先加一个“下载安装”按钮再补安全边界。

新节点声明 bootstrap 有一个刻意收窄的例外：SSH host key 已由操作者带外确认、
受信 preflight 已证明内核支持和 root/免密 sudo、且 `/usr/bin/wg` 缺失时，固定
脚本可通过受支持的系统包管理器安装 `wireguard-tools` 并立即复检。它不升级已安装
版本、不作用于现有 fleet，也不声称具备 canary 或包级回滚；失败时 SSOT 不变。
