**日期** 2026-08-23 · **状态** 生效

发布器最自然的写法是"SSOT 变了就发布"。不够。

分发点会以别的方式和真相分叉:被清空、推到一半断线、有人手工动过。只盯文件
变化的发布器对这些无能为力 —— 而它们的表现是"全网停在一个旧快照上,而中控
认为一切正常"。

所以每一轮都比对**分发点当前指向的快照**与**本地算出来的**,不一致就重推。
这和 [D33](D033.md#d33--期望状态不只是文件内容)(pull 不按快照 id 早退)是同一条
道理:**期望状态要主动核对,不能等事件通知。**

同一轮里还多做一件事:推完从**节点视角**再取一次。推成功不等于取得到 ——
nginx 路径写错时推送侧完全正常。加上这条检查的第一次运行就抓到了中控自己的
DNS 问题(那台机器上有个无关的 WireGuard 接口把所有域名劫走)。
