生产节点的管理 SSH 均可从中控直达。`reverse_only` 只约束 WireGuard 隧道的发起
方向，过去据此把 SSH push 限定为 bootstrap 是把数据面约束误套到了管理面。

操作者触发的代码发布因此默认先用 `loom release` 记录精确 commit 和制品，并立即
用一次性 `loom publish` 固化对应 signed current；随后通过 SSH + SCP 把同一二进制
并行直发所有当前节点：远端临时落盘、核对 SHA-256、原子
替换并重启实际运行的 Loom 服务。命令完成以各节点 SSH/SCP/激活返回为准；默认不
再等待 publisher 的 30 秒周期、pull 的 45 秒加抖动或 6/6 状态轮询。失败必须指出
具体节点，不能把部分成功写成全部成功。

这只改变交互式代码制品的快速传输路径，不取消 D91：`loom release`、签名快照、
多镜像和 signed pull 继续负责发布记录、配置与秘密边界、离线节点补齐和长期漂移
纠正。直发不得原地覆盖正在运行的二进制，也不得绕过放行记录或签名配置。
