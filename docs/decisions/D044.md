修正 [D43](D043.md#d43--56-曾经假设地址不影响该选哪条链这是错的) 有两条路:让目标
集合开放、按目标学习;或者**让中控声明服务清单,接入端只能从中选**。

选后者。它一次消掉三个难题:

| | 开放目标集 | 服务清单 |
|---|---|---|
| 冷启动 | 第一个请求必然是猜 | **不存在** —— 服务上线前就能测完 |
| 分组 | 靠域名后缀 / ASN 推断,会错 | **已知**,声明的 |
| 被动观测 | **必须**(没有别的数据来源) | 回到"优先但可选" |

还有两个额外的好处:

**安全边界。** 接入端能指定任意 URL,意味着一份泄露的凭据能把服务器变成开放
代理。§8.2 的准入校验只管"允许走哪",服务清单把它扩展到"允许去哪"。

**请求带上了语义。** "我要服务 X"而不是"我要这个 URL",于是按服务的配额、
objective、归因才成立。

推论:如果服务按地址集合声明,数据平面可以**从请求的 host 反查服务** ——
接入端连"我要哪个服务"都不用说,这才是完整的"接入端不知道任何事情"。

代价是任意 URL 用不了。而这应当是一个**显式声明的服务**("我不知道里面有
什么" + 明确的兜底策略),不是默认假设 —— 区别在于显式声明时你知道自己在
放弃什么。
