**日期** 2026-08-27 · **状态** 生效 · **相关** [D81](D081.md#d81--身份签名之后转述来的节点也能核对版本收窄-d73)、[D86](D086.md#d86--组件版本先闭合观测再增加自动升级)

新 writer 直接把 v3 换成 v5 会让旧 reader 验签失败；在 gossip 拓扑里这不是
短暂少一个字段，而是旧节点拒收新节点、`/status` 503 和转述分区。因此阶段 A
由 writer 同时发旧 reader 能验的 v3 与完整 v5，新 reader 两份都验；旧 reader
忽略 `attest_extended`，滚动窗口仍保持连通。

双签不能永久作为结束态：relay 可以剥掉扩展签名和新外层字段，只留下仍合法的
v3，把组件漂移或候选全失败降级成“没有数据”。所以 SSOT 增加
`defaults.attestation_min_version`。阶段 A 保持 0；确认所有节点 reader 已升级后，
阶段 B 单独改成 5。此后 report、CLI、UI、gossip 与 Agent 剪枝共同拒绝没有 v5
的观测，剥离变成明确故障。不能在阶段 A 首次发新二进制时就设 5，也不能升级
完成后永远忘记收口。

当前生产已经完成 phase B，`attestation_min_version=5`。新 producer 直接把 canonical
v5 放入主 `attest`，不再复制迁移期的 legacy + `attest_extended` 双签写法。

“确认”必须是可执行闸门，不靠逐页目测：每台 report 节点（包括没有入站角色的
接入节点）都必须有自己的节点证书；CLI 从本机 `127.0.0.1:61802/status` 读取与
远端同源的后台 Observation。只有
`loom status --require-attestation=5 <ssot>` 显示全部适用节点 ready 且退出码为 0，才允许切换。
