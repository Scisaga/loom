**日期** 2026-08-23 · **状态** 生效

配对失败的方向不对称:**新版通常读得懂旧配置,旧版读不懂新配置。**

不是推测。发布器崩过一次:它跑着旧二进制,而 SSOT 里多了 `services` 字段,
于是直接拒绝发布,而症状是"改了 SSOT 但全网没动"。

所以 `loom pull` 换完二进制**就结束这一轮**,配置留给下一次(几分钟后)。
继续用当前进程里的旧代码去装新配置,正是要避免的那种配对。

二进制的 SHA256 进签名过的 manifest,而 manifest 的内容哈希就是快照 id ——
**换二进制就换快照 id**。§15.4 要的"配置与二进制绑定回滚"因此是结构性的,
不靠任何约定。

分发树里它内容寻址(`bin/<sha256>`,顶层共享):同一个二进制不重复推送,
回滚到旧快照时旧二进制还在。
