**日期** 2026-08-31 · **状态** 已实现 · **相关** D89、D94、D95、§4、§5.1

节点加入后只生成节点、隧道和固定出口声明，会让 `egress_axis:any` 的自动策略仍停留
在旧 `allowed_servers` 集合；拓扑已经看到新节点，但 Agent 永远不会把它枚举为候选，
形成“节点可作出口、规则却不认识它”的双重事实。Add Node 因此必须把规则对账纳入同
一份预览、完整校验、revision guard 和原子保存事务，UI 同时展示即将扩展的策略池，
不能在提交后靠另一个后台任务补写。

系统不按 `best-egress` 这类历史名字判断，也不把所有 `egress_axis:any` 都当成无限池。
只有在新增前已经包含每个在役 `egress_capable` 节点的显式池，才被识别为“全量自动
池”并加入新出口；漏掉任一现有出口的地域池、灰度池或人工 allowlist 保持原样。没有
既有出口时无法从集合推断意图，也不擅自扩展。新增非出口节点同样不会触发规则扩展。

自动池复用原声明及既有凭据，不产生新的秘密分发需求。为新节点补出的固定出口声明
仍属于新的授权对象；在控制面尚未拥有各接入节点的可信管理地址、主机身份和最小秘密
分发事务之前，UI 必须继续标记 `credentials pending`，不得复用密码或把未授权声明
显示成可选项。
