**日期** 2026-08-24 · **状态** 生效

把源头存档加进 `loom backup` 默认清单之后,**备份当场整个不干活了** ——
`deploy/ssot-history` 要发布器成功发过一次才建,而在那之前它不存在,
于是原有的"少打包了什么就硬失败"把整次备份拒了。

原来那条硬失败是**对的**,不能放松:一个"成功"但内容不全的备份,只有在
需要它的那天才会被发现。所以改成分两类:

| | 缺了怎么办 | 为什么 |
|---|---|---|
| `secrets.env`、`pki` | **硬失败** | 它们不存在意味着这台机器有别的问题 |
| `ssot-history` | 说一声,继续 | 它可以合法地还没出生 |
| 命令行显式点名的 | **硬失败** | 人写出来就是指望它在 |

**"可选"说的是它可能还没出生,不是它不重要。** 所以缺了仍然要打印出来 ——
静默省略就是在制造"你以为你备份了",与那条硬失败是同一个理由,只是不该
拦住整次备份。

> 分错边的代价不对称,这是关键:必需项当可选 → 备份看起来成功但少东西;
> 可选项当必需 → **一台刚起来的中控连备份都做不了**,而"做危险变更之前先
> 备份"恰恰是最需要它能跑的时候。
