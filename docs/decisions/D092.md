**日期** 2026-08-29 · **状态** 已实现、待部署 · **相关** [D89](D089.md#d89--控制中心是-ssot-的事务视图不是第二套网络模型)、[D90](D090.md#d90--流量历史只由可信相邻-counter-样本推导)、§16.4

左右两列虽然能画出当前六节点的九条持久边，却把布局偶然性冒充成网络分层，并在
节点增加后迅速形成密集交叉。拓扑改为两个同心椭圆环：能接受反向建连的节点等距放在
内圈，`reverse_only` 节点等距放在外圈；两环使用半步角度错位。这里的内外只表达
WireGuard 建连职责，不代表内网/公网、安全级别、地理距离或控制层级。没有 direction
元数据的旧节点视图继续使用确定性分组，而不是从 IP 或城市猜角色。

持久 WireGuard 边显示三个不同语义的观测值：最新一分钟观测中的 RTT、近五分钟可信
TX counter 差值换算的实际传输速率，以及近十五分钟连续 RTT 摘要的 P95−P50。第二项
是窗口内实际经过链路的 throughput，不是容量测试得到的 bandwidth；第三项是多个
一分钟五样本中位数之间的滚动变化，不是 packet-level jitter。界面必须明确写出窗口，
缺少相邻 counter 或至少两个 RTT 摘要时显示缺失，不得补成零。

为避免修改已经部署的 `loom-attest-v5` canonical bytes，控制节点在本地 traffic JSONL
frame 里保留通过现有身份/测量门禁的 `report.neighbors` 摘要，读取时按节点、邻居和
观测时间去重，再按无向链路计算滚动分位数。重复收集同一份 gossip 陈述不能增加样本，
同键异值必须失败关闭。流量仍完全复用 D90 的 independently signed `loom-traffic-v1`
相邻差值。候选虚线没有连续探测和 counter，因而不显示这些指标；它们仍只代表 SSOT
允许的按需路径。

内圈节点之间没有常驻 WireGuard 边时，不能拿 Agent 的完整候选路径观测拆成单跳
指标：例如 `demo-d → demo-b → demo-e → 目标站点` 的耗时同时包含多个网络段以及目标响应，
把总数贴到 `demo-d ↔ demo-b` 会失真。每个可公网直拨的内圈无向对因此只派生一个真实
可拨方向，使用隔离凭据经 Hysteria2 请求对端 loopback 上的固定响应，并签发独立的
`loom-linkmetric-v1` 陈述。标签显示该方向的单跳响应延迟、十五分钟 P95−P50 与固定
响应的 achieved probe throughput；最后一项只是主动探测速率，不是业务流量或链路
容量。方向必须在 tooltip 中披露，缺样本显示 warming up，不能用候选路径数字补齐。
