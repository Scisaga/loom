# D97 · 客户端路由偏好收敛为 Direct、Auto、指定出口三模式

**日期** 2026-08-31 · **状态** 设计生效，客户端 selector 与 UI 待实现 · **相关** D94、D95、D96、§4.6、§7、[客户端接入设计](../client-access.md)

D95 把设备默认声明定义成“仅在 Service 未命中时生效的 catch-all”，这不能表达实际
需要的三个互斥顶层模式。本决策取代 D94、D95 中关于客户端可写路由偏好的部分；
已经实现的 `access.default_declaration` 与 `/api/control/default-exit` 不删除，但
只保留为 Auto 模式下的中控 catch-all，不能包装成三模式已经交付。

客户端只提供一个三态控件：Direct 让全部接管的业务流量从设备本地直连；Auto 完整
执行中控签名下发的 `Host → Service → Policy`，完整路径由 Agent 自动选择；指定出口
从全部在役 `egress_capable` 节点中选择最终出网节点，全部接管的业务流量固定该末跳，
到达它之前的中继仍由 Agent 自动择优。当前部署的全部节点均具备出口能力，因此都会
出现在指定出口列表；若以后某节点明确关闭 `egress_capable`，它不再是有效出口。

三种模式复用同一个 TUN/mixed 接管面，不增加端口。客户端不得选择接入节点、首跳、
中继或完整路径；Current Paths 始终是只读运行时观测，也不得出现 `Apply`。三态偏好
由客户端本地原子保存和切换，控制面离线时仍依据最后一份已验证配置工作；它可以作为
状态观测上报，但不写入 SSOT，也不为每次切换触发发布。中控只签名下发 Auto 规则、
可用出口集合与既有授权材料；客户端不得编辑 Policy、候选集或生成的 sing-box 配置。
若所选出口在新配置中被撤权，客户端明确标为不可用并 fail closed，不静默改成其他
模式。正式交付只需补齐本地 selector、受保护偏好存储和 UI，不能复用 catch-all 字段
暗中改变其旧语义。
