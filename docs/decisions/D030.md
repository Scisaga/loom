**日期** 2026-08-22 · **状态** 生效

`loom apply` 之前,部署是我一条条手打 scp 和 ssh。三个常驻进程 × 五台机器,
每次都可能漏掉一步 —— 而且**只有我能部署**。

固化下来的顺序是:暂存 → 预检 → 存 previous → 就位重启 → 验证,失败回滚
(§14.2.1)。不是想出来的,是每一条都对应一次真实的失败:

| 步骤 | 对应的坑 |
|---|---|
| 预检在覆盖之前 | 直接覆盖再重启,配置非法 → sing-box 崩溃重启循环,而我只测了新功能 |
| 只重启文件变了的服务 | 一律全重启的话,改一行 sing-box 配置也会断三条隧道 |
| unit 文件变化重启对应常驻 service | `ExecStart` / Capability / sandbox 只有新进程才生效；只 `daemon-reload` 会被旧进程的 active 假绿骗过 |
| 验证前先等几秒 | 崩溃循环的第一次崩溃在启动后一两秒,立刻查会看到 active |
| 回滚只碰动过的东西 | 实测:预检失败(什么都没装),回滚却重启了三条隧道 |

另外 **wg-quick 不能用 `systemctl restart`**:down 与 up 之间有竞态,报
`` `wg-xxx' already exists ``,而后果是 **unit 停在 failed、接口其实还在、
隧道看起来是好的** —— 最难查的那种状态。必须显式停、`ip link del`、再起。
