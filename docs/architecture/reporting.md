## 度量与可观测

**这是 Loom 的核心能力,不是配套设施** —— [调度](scheduling.md#调度) 的整个调度机制建立在它之上。

Agent 的制品、配置绑定及更新事务由[配置分发](distribution.md)定义；上报组件只观测状态，
不因读取到新版制品而自行决定发布或触发另一轮升级。

### 采集什么

| 层次 | 指标 | 观测点 | 用途 |
|---|---|---|---|
| **网络层** | RTT、丢包、抖动、握手成功率 | 隧道两端(Agent) | 服务器轴选优 |
| **应用层** | TTFT、tokens/s、错误率、响应结构 | **只能在 L7**:地址侧埋点 / L7 网关 / 调用方 SDK([被动观测优先,但被动能看到什么由观测点决定](measurement.md#被动观测优先但被动能看到什么由观测点决定)) | 地址轴选优 |
| **调度层** | 切换事件与原因、各候选实时评分 | 接入节点 + 控制平面 | 判断阻尼参数是否合适、是否振荡 |
| **运行层** | 流量、连接数、凭据用量、Agent 签到 | 服务器 + 控制平面 | 容量规划、异常与失联发现 |

### 两个角色:决策者与上报者

"Agent"这个词很容易盖住两件不同的事。它们的部署位置、权限、和"能不能有
多个"都不一样:

| 角色 | 做什么 | 装在哪 | 多一个会怎样 |
|---|---|---|---|
| **决策者** | 排序、切 selector | 每个**接入节点**恰好一个 | 两个互不知情的决策者互相顶掉对方的选择 |
| **上报者** | 观测、自检、如实说 | **每个节点**,服务器也要 | 无害,它不做任何决定 |

服务器上没有 selector 可切,所以不装决策者 —— 但这不等于服务器上不需要跑
任何东西。**DDNS 重解析、隧道断连、有人手工改了配置,这些只有节点自己知道。**

上报者回答两个问题,都不需要任何决策权:

1. **隧道观测是否新鲜** —— 记录每条受管隧道的握手年龄与收发字节；超过配置阈值
   标为 stale，接口缺失与从未握手分别报告。新鲜握手不等于端到端业务健康。
2. **配置还是渲染出来的那份吗** —— 按 `loom hydrate` 产出的清单逐个文件
   比对哈希，规则见[幂等收敛](deployment.md#幂等收敛)。

#### 不是所有变化都是问题

事件按**类别**分级,不靠猜取值:

| 级别 | 是什么 | 例子 |
|---|---|---|
| `info` | 系统正常工作的记录 | 发布了新快照、Agent 换了条路 |
| `problem` | 需要人看一眼 | 隧道 down、配置漂移、目标不可达 |
| `ok` | 从问题状态恢复 | 隧道 down → active |
| `pending` | 过渡态:现在正常,但不该一直这样 | 凭据轮换的两代并存窗口([凭据轮换:必须分两步](identity.md#凭据轮换必须分两步)) |

快照 hash 和选路变化是正常事件，不能靠取值白名单把它们判成问题；分类错误会让噪声
淹没实际故障。

#### "没有后续"不等于"还在持续"

重启后的首轮静默播种不会补写全部历史变化。判断问题是否仍持续必须核对当前有效状态，
不能只看日志是否出现后续事件。持续时间和未知时刻见[事件契约](events-topology.md#事件只记变化不记状态)。

#### "没有问题"也要说出来

一片空白分不出"一切正常"和"这功能没在跑"。所以没有未解决项时明确打出
`✅ 没有未解决的问题`。

#### 三个容易做错的地方

**只报配置里列出的接口。** 机器上可能有与 Loom 无关的 WireGuard 接口;
把它们算进来,别人的接口一断这台机器就整体报不健康。反过来:**列在配置里
却在 `wg show` 里找不到的接口是"隧道没起来"**,这是最该被看见的状态,而在
"只报看得见的"那种实现里它完全隐形 —— 表里少一行,没人会注意。

**v1 `/status` 只绑隧道内地址。** 此接口没有自己的请求身份认证,它靠 WireGuard 兜住:能连上
隧道内地址,就已经持有隧道密钥了。再加一层口令只是多一个要分发和轮换的
秘密,换不到实际的隔离。代价是绑错地址后果严重且无症状 —— 所以这是**加载时
的硬错误**,不是文档里的一句提醒。没有隧道的纯接入节点绑回环:远端拉不到,
但本机的配置自检仍然可用。

这段只描述 v1 `/status` 拉取与 gossip 边界，不表示回环可被中控访问，也不替代
[v2 Device mTLS 报告服务](../protocols/control-plane/device-services.md)。v1 中没有受管 WireGuard
入站的 enrollment Device 使用 [signed pull 与管理面快速发布并存](distribution.md#signed-pull-与管理面快速发布并存) 的签名
`Observation` 公网适配器；该入口的认证来自 CA、现有签名域、registry 当前 SPKI
与 SSOT 在役身份的共同约束，不把 `/status` 直接公开。

**采集失败与"一切正常"必须分得开。** 空的隧道列表既可能是没有隧道,也可能
是 `wg` 跑不起来。后者要单独记进 `errors`,否则一台采集器坏掉的机器看起来
和一台健康的机器一模一样。

#### 覆盖面由拓扑决定,且必须说出来

接入节点只和一部分服务器有隧道,而 `AllowedIPs` 是 /32 —— 拉不到隧道那头
以外的地址，不能假设任意接入节点都能直接读取全网报告。

但**握手只能证明相应 peer 的一次握手事实**，不能单凭一端握手年龄断言两端当前健康
或全网覆盖。观测覆盖范围必须按实际来源、对应隧道与新鲜度列出；未收到有效证据的
节点或链路保持未知。

配置自检不对称,够不到的节点只能靠本机执行。`loom status` 会**明确列出**
够不到哪些节点:一张只有三行的表,看不出是"三台都好"还是"还有两台没查"。

### 按段量,不按整条路线量

有两种测法,差别不只是效率:

| | 做法 | 代价 |
|---|---|---|
| **按路线** | 接入节点把每条完整候选链跑一遍 | 候选数是 `1 + N + N(N-1)`,串行探测;同一个事实被反复发现;每个接入节点各来一遍 |
| **按段** | 每台机器只量自己能量的那几段,互相交换 | 每台 `N-1` 段,**并行**;一个事实量一次全网复用 |

例如一台服务器到某个目标不可达：逐完整路径扫描会在每条经过它的候选链、每个客户端
重复发现同一事实。由服务器在既有预算内观测并签名转述后，客户端即可复用。

#### 每台机器量两样

1. **到每个隧道邻居的 RTT** —— 一次 TCP 建连。不用 ICMP:那要 `CAP_NET_RAW`,
   而上报者只该有读 `wg` 需要的 `CAP_NET_ADMIN`;建连时间还有个好处,量的是
   应用真正会走的那条路。
2. **直接访问每个目标地址的结果** —— 通不通、多少毫秒。
   **这是最值钱的一项**,因为它是关于**这台机器**的事实,与任何链路无关,
   所以能被所有接入节点复用。

服务器采集目标合并声明的 `probe_url` 与 Service 的具体地址（HTTPS 根路径），
跳过域名后缀规则，并按 HTTP(S) 空路径与根路径等价去重。采集沿用服务器既有周期；
节点 `probe_targets` 继续独立标识出网健康检查，客户端只复用服务器观测。

#### 转述:没有隧道也能听到

接入节点不一定和每台服务器都有隧道 —— access-a 就只和 edge-a、edge-b 有,而上报
接口只绑隧道内地址。

在 v1，**额外加隧道当然能让上报端口互通，但不值得为监控复制数据平面。** 两个节点即使
能通过公网 Hysteria2 承载业务，也可能因报告接口只绑定常驻 WG 地址而存在观测通道缺口，
这不等于数据平面不可达；转述继续补这个兼容缺口。目标 v2 的 `device_report` 只经 Device
的 permanent overlay/private service directory 到达 control，不为监控另开公网 HTTPS role，
也不从 data-ingress 可达性推导报告权限。

转述绕开了它:每个节点只向**直接邻居**拉,而邻居返回的内容里已经包含了**它**
听来的那些,一跳一跳自然传开。cn-a 够不到 access-a,但够得到 edge-a;access-a 问
edge-a,就拿到了 cn-a 的观测。能听到哪些来源由实际收到且验证通过的观测决定。

三条规则:

- **同一个观测者只留最新一份。** 转述会让同一份数据从多条路径回来。
- **过期的直接丢掉,不是标记。** 一份 15 分钟前的"能到"比没有更危险 ——
  它看起来是数据,实际是回忆。
- **观测者字段是"谁量的",转述时原样保留。** 改掉就分不清数据来源了。

v1 Linux Agent 经 `/status` 读取和验签。v1 NAT 客户端报告 POST 的观测读取
契约与各平台消费边界见
[客户端观测复用说明](../clients/observations.md)。URL 只在消费时允许 HTTP(S)
空路径与 `/` 等价，其他路径、转义、查询均保留，不改动已签名测量正文。

#### 用法一:剪枝

出口已知打不到目标的候选，在现有授权预算内无需重复探测该失败事实。剪枝**每轮按新观测重取**,不是一次性判定 —— cn-a 什么时候
恢复,下一轮自动重新开探。

被剪掉的候选是**当轮已知不可用约束**，原因写入决策记录，不增加本机探测样本：

- 当前选择若被剪掉，其旧成功样本不能掩盖新的服务器失败证据；有实际可用的
  授权候选时，按既有故障避让规则离开当前路径。
- 不把同一份服务器观测每轮重写成新时间的失败样本，也不把它累计进本机失败率。
  旧 `observation_kind: derived` 记录仅作诊断历史，不参与数值排名。
- 约束仍依赖原来源与原时间；观测恢复或过期后解除，不留下延长寿命的派生故障。
  **推论与亲测必须分开**，回放时才能分清真正发生的请求([回放与回测](events-topology.md#回放与回测))。

**三个状态必须分清:已知能到、已知不能到、不知道。** 只有第二种能剪 ——
把"不知道"当成"不能到",一台刚加进来还没被观测过的服务器会永远不被尝试。

#### 用法二：分段合成估计

有了各段的数字,链路质量可以**算**而不是**测**:
`access-a→cn-a` + `cn-a→edge-a` + `edge-a→目标`。

好处是新接入的设备不必从零攒样本 —— 拉一份现成的表就能排序,几秒而不是
半小时。**代价是算出来的不等于测出来的**：延迟大致能相加，但每多一跳多一次
握手，还有排队和分片。所以 Linux Agent 可以**用估计排序，再在既有候选测量预算内
验证**。Windows/Android 原生客户端的适用规则见
[客户端消费边界](../clients/observations.md#客户端消费边界)，本节不为其新增测量授权。
