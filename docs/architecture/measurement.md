## 被动观测优先,但被动能看到什么由观测点决定

**两个约束同时成立,方向相反。**

**约束一 · 主动探测要花真金白银。** 在推理场景下,TTFT 和 tokens/s 只能靠发真实推理请求测出来 —— 这与 ICMP 的成本结构完全不同。所以真实流量的被动观测应当是主数据源:零额外成本、零额外暴露、且比合成探测更准确。

**约束二 · L4 隧道看不到应用层。** Loom 的数据平面是加密隧道 + L4 代理([访问契约:换地址能不能只靠 L4 完成](model.md#访问契约换地址能不能只靠-l4-完成)),**流量对它是不透明的**:TLS 之后没有请求边界,HTTP/2 多路复用后连"这是第几个请求"都不知道,QUIC 的应用流与请求内容同样不能由这个观测点解读。

于是被动观测能拿到什么,完全取决于**观测点在哪一层**:

| 观测点 | 能拿到 | 拿不到 | 前提 |
|---|---|---|---|
| **L4 隧道 / 代理**(总是可得) | 建连耗时、**首字节返回时间**、字节数、连接时长、RST 与超时、并发连接数 | tokens/s、响应结构、错误码、请求边界 | 无 |
| **自有端点埋点** | 全部应用层指标,且最准 | — | 端点是自己的(`managed: true`) |
| **L7 网关**([访问契约:换地址能不能只靠 L4 完成](model.md#访问契约换地址能不能只靠-l4-完成)) | 全部应用层指标 | — | 引入网关组件 |
| **调用方 SDK / OpenTelemetry** | 全部应用层指标 + 端到端体感 | — | 调用方代码可改 |
| **主动契约请求**([等价类:标签不足以保证可替代性](model.md#等价类标签不足以保证可替代性)) | 全部应用层指标 | — | 花钱,须限频限额 |

> **v1 流量统计协议边界:** report 把 Loom
> 管理的 WireGuard 接口累计 RX/TX 放进独立的 `loom-traffic-v1` 签名域。它作为
> Observation 的可选附件转述，因此不改变既有 `loom-attest-v5` canonical bytes；
> 新节点必须独立验证 CA、节点身份、签名、新鲜度以及外层 node/TS 绑定后才能使用。
> 中控只对同一 node/interface/peer/counter-epoch 的**相邻可信样本**计算 delta。
> renderer 固定每 60 秒采样，中控固定把超过 3 分钟的间隔视作 gap，并保留 30 天；
> 这个阈值随写入 frame 固化，重启或以后修改实现不会重新解释旧历史。epoch 变化、
> counter 回退和超过上限的采样 gap 都是拒绝的 transition：
> 不产生字节，也不被画成零流量。Overview 展示所有节点 WG 接口 RX+TX delta 的
> 时间桶，因此是按隧道 hop 加权的基础设施负载，不是唯一应用 payload；Node detail
> 分开显示该节点 RX/TX；Topology 对每条无向链路只累加两端各自的 TX delta，避免
> sender TX 又以 receiver RX 重复计数，并显示实际收到的单端/双端样本；“桶里有
> 样本”不证明所有预期接口都上报。普通节点网页与 `/traffic.json` 只把本机直接
> 观测映射成 current counter，本地不保留 30 天历史；中控额外附带同一历史桶。
> `/traffic.json` 是版本化抓取契约，64 位 byte 值编码为十进制字符串，并按一次
> gossip 轮次缓存；`/status` 是诊断状态，可能同时含转述的签名附件，不能当作稳定
> 的本机流量 API。该闭环不观测 direct、
> Service/sing-box 或 Hysteria2 流量；没有对应 L7/数据平面采集器时不得把它们归入
> WireGuard 柱状图。

> **v1 远端健康转述协议边界:** `healthy` 不能由 relay 的 HTTP 503/200、
> 外层 Observation 或若干局部字段推断。每个节点在观测轮次用真实 `Collect`
> 结果汇总 Tunnels、Drift、Errors、Components、Rollout 与 Agent 等完整
> `Status.OKAt` 判定，生成有严格限长、排序和去重的问题列表，再以现有节点 TLS
> ECDSA 身份签入独立的 `loom-selfcheck-v1` 域。它是 Observation 的可选附件，
> 不改变 `loom-attest-v5` canonical bytes。reader 只有在 CA、证书节点名、签名、
> 新鲜度以及外层 node/TS 绑定全部通过后才使用：显式 `healthy=true` 且 problems
> 为空才标绿，显式失败标红；附件缺失（包括滚动升级中的旧 reader/producer）保持
> unknown。这样转述路径可以带回远端最终健康，同时不能替远端伪造绿灯。

> ### 不变量
> **`tokens/s` 与响应结构不是 L4 能被动观测的量。**
> 声明用它们做目标函数,就等于声明必须存在一个 L7 观测点。**没有 L7 观测点的候选只能用 L4 指标排序** —— 连接的首字节返回可能只是握手数据，不能据此识别模型的首个 token；TTFT 必须在具备请求和 token 边界的观测点测量。

**因此:**

- 有 L7 观测点的候选,被动观测是主数据源;
- 只有 L4 观测点的候选,**主动契约请求是拿到应用层指标的唯一途径**,必须限频、限额;
- 主动探测只覆盖**没有真实流量的候选**;
- **探测预算本身要计入成本核算**,并在评分中体现;
- **主动探测测的是路径质量,不是服务质量。** 用一个对所有候选相同的中立目标,
  候选之间的**相对排序**有效 —— 这正是服务器轴需要的([两个选择轴](model.md#两个选择轴))。它说不了任何
  关于地址轴的事:比较等价类里几个地址的好坏要看 TTFT、tokens/s、响应结构,
  那些只能从 L7 观测点拿;
- `Measurement` 必须记录 `observation_point`([数据模型](credentials-model.md#数据模型))—— **不同观测点的数据不可直接比较**,拿 L4 近似值和 L7 真值一起排序会得出错误结论。


## 首字节时间与吞吐是不同指标

首字节时间短不代表持续传输快。Linux/server Agent 应在既有授权测量预算内分别记录
首字节耗时和满足采样要求的响应速率，按 objective 使用对应指标。

| objective | 排序指标 |
|---|---|
| `latency` | 首字节时间的 p50 |
| `throughput` | 有效响应体测得的下载速率 |
| `stability` | 首字节时间的 p95 |


增加中继可能增加握手、排队、加解密或封装成本，但不存在“每跳固定损失四分之三吞吐”的
通用比例。不得把历史样本转成固定路径评分惩罚；候选仍按策略约束和可比较的有效观测选择。

### 测不出吞吐时必须说出来,不能并列最差

响应体不足最低采样要求时，不能把首字节倒数当成吞吐。当前 Agent 的最低响应体门槛为
32 KiB；`objective: throughput` 没有有效样本时必须说明样本不足，不能靠候选名称产生排序。
具体源码能力见[实现对照](../development/implementation.md)。这项服务器测量契约不扩大原生客户端预算。

## 探测预算:有界,而不是全探

本节描述 Linux/server Agent 的候选窗口。Windows/Android 的预算统一见
[客户端消费边界](../clients/observations.md#客户端消费边界)，不适用下述候选轮询。

候选数是 `1 + N + N(N-1)`。加上"每次探测要读正文才算得出吞吐",全探不可持续:

```
15 条候选 × 2 个目标 × 读 256KB = 每轮 7.5 MB
每 5 分钟一轮                   = 每小时 90 MB
```

**探测本身会变成网络上最大的一股流量。**

有界之后:

- **当前选中的那条每轮必探** —— 它变坏了要立刻知道,这为立即离开已知失败候选提供依据；
  阻尼不能保护已经不可用的当前选择
- 其余按游标轮换,保证每条迟早轮到
- 少探了多少**要说出来**:静默截断会让"这一轮没试到"看起来像"试过了但不行"

预算演算示例（合成值，不能作为当前运行指标）:

```
全探  66 次 / 5 分钟   = 792 次/小时
有界  22 次 / 10 分钟  = 132 次/小时     还没算剪枝
```

### 预算引入了一条新的算术约束

有预算之后,一条候选**不是每轮都被探到**,而是平均每 `候选数/预算` 轮才
轮到一次。窗口里能攒到的样本数因此要打折:

```
每条候选的样本数 ≈ (window / tuning_period) × (budget-1) / (候选数-1)
```

小于 `min_samples` 时,排序永远不会启动 —— 和 [Agent：调参回路的唯一执行者](agent-runtime.md#agent调参回路的唯一执行者) 那条"窗口装不下
min_samples"是同一类错误,只是原因从"窗口太短"换成了"预算太小",而症状
一模一样:配置看着完整,日志里只说"没有候选达到 min_samples"。

校验器现在算这一条,并给出三个可选的修法(放大窗口 / 降低门槛 / 加大预算)。

**`stale_after` 也要比轮换周期宽**,否则每条候选在轮到之前就先"过期"了。
