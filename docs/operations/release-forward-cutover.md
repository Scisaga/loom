本提案尚未获准，不是已经启用的迁移算法。既有显式服务更新继续有效；只暂停会改变自动安装接受
依据的操作。用户已确认没有已知旧签名备份，不再重复搜索已查目录。

## 必要背景与选择

六节点保留的旧防重放记录与找到的旧签名文件不对应，因此不能证明旧记录到新安装包的原始签名
关系。现运行程序已由用户授权显式替换；它们的实际字节、原签名包、连续发布公钥及当前普通期望
引用可以独立核验。两种选择是：继续保持显式更新，或由用户一次性明确授信这组已授权、正在运行且
独立验签的程序，建立现行安装包接受起点，再完成自动消费。

推荐后一种。它不补造丢失的旧签名，也不声称恢复了旧发布历史；缺失的那段原始绑定由操作者对
明确现程序的授信替代。原 floor 保持原位、原字节，身份、密钥、认证高水位及 latch 不变。
新旧代属于不同签名对象，不把数字大小当作连续性证明。

## 已核实的具体起点

受保护的 `deploy/evidence/2026-10-12-automatic-release/forward-alternative-review.json` 固定各节点的
原 floor、原运行程序、原签名 catalog/manifest 及普通期望关系。完整包与逐文件摘要已独立验证；
六节点在本轮 Windows 发布后的实际程序、数据面和原 floor 也已并行读回。起点取匹配现运行程序的
原签名包，不取较新下载目录中的其他程序，也不重新签署或改写原件。

这份证据只证明现程序及新域的明确起点，不能证明丢失的旧载荷。不同节点不得因同包或同代就省略
身份、原 floor 与实际执行的核对；现场变化使对应节点停止切换写入，保留其当前可验证状态。

## 最小模型与正式入口

继续使用现有 Linux Manifest、内容目录/current、平台公钥、DeviceIdentity/LKG/Preference 和
ExpectedComponent，不新增安装权威、迁移 store、receipt、协议版本或旧格式 decoder。

一次性安装操作须显式固定预期原 floor 摘要、现程序对应的原规范 manifest、设备身份及当前执行
输入；它们是本次命令参数及受保护审核输入，不进入 `.env` 或常驻配置。正式入口沿
`loom client install` 扩展一次性接受操作，目前尚未实现，不能把下面的目标链当作现有命令能力。

| 层 | 目标对应 |
|---|---|
| domain | 原已签 Manifest 的接受前沿；原 Device 和普通期望不变 |
| wire | 原 schema 3 catalog、manifest、签名与私有设备认证；不修改已签原文 |
| persistent | 同一内容目录/current 承担现行包接受前沿；原 floor 仅原位保全为退役证据，不参与正常解码 |
| runtime | 同一安装器从完整原包建立规范安装布局，原设备与资源输入继续消费；自动更新只执行获授权的精确期望 |
| UI/CLI | 期望、所选原 manifest、真实执行摘要及读回时间分别展示，不以目录 current 宣告已应用 |

首次接受必须先核对现程序和包内程序、数据面均相同，原 platform trust 不变，原 floor 与身份均符合
本次固定输入。不能用此操作把任意较旧程序、另一设备或另一签名公钥当作起点。普通升级仍使用原
manifest 代规则：低代拒绝，同代异值拒绝，同代同值幂等；旧格式始终拒绝。

## 实现与失败恢复的完成条件

1. 在现行安装锁内重读固定输入，验证完整包、原公钥、设备身份、实际程序、原 unit 和精确所有权。
   规范内容先耐久落盘；未知目录、变更过的原件及遗留旧权威路径拒绝，不以一次 inspect 免除重读。
2. 沿正常 service 入口停止旧 generation 并确认精确清理，再提交现行包接受引用及相同设备执行输入。
   提交前失败不改变原接受依据；提交后失败保留新接受前沿和设备认证状态，保持 failed/inactive。
   重启及重试只从原规范 manifest/current 与 Device 状态恢复，不从日志、缓存或旧 floor 恢复运行。
3. 自动消费通过同一私有设备认证取得普通期望所引用的原签名发布材料，并独立核验完整实际字节。
   保持 DeviceView 的既有四字段组件坐标；不从公开 current 自行授予升级权限，不改期望事实。
   无期望、引用缺失、歧义或暂时不可达时保持当前仍获授权的可验证执行并报告实际范围，不降代或复用旧协议。
4. 同机隔离验收正常接受、拒绝与失败恢复后，才执行已获批准的生产切换；独立节点并行，同节点按
   因果顺序。独立管理入口、变更前快照及原网络所有权保留，Linux 默认 Mixed，TUN 不进入初始 netns。
5. 正常入口改变一项明确期望后，节点真实拉取、自动安装、进程与业务消费、原始报告及重启回读均须
   成立；删除被替代的执行入口和程序，保留签名历史、原 floor、身份与仍被引用的原件。不能只关闭布局接管。

最小验证覆盖：正确绑定与变更后拒绝；低代/同代异值/旧格式重放拒绝；错钥、错平台、正文损坏和
错设备拒绝且原件保持；接受前后中断、重复执行及重启；期望引用与下载 current 不同、报告迟到及
另一服务继续；最后是精确生产制品、正常业务和旧入口删除。只按新风险增加检查，不重演已覆盖的完整传输矩阵。

本提案尚缺用户对替代授信起点的明确决定，以及安装接受、私有交付和自动运行的软件接线与相应
真实验收。以上是本核心工作项的全部剩余链，不能把已有签名分发或本提案写成自动更新完成。
