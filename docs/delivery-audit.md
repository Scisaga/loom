### 本工作项已确定的规则与继续顺序

以下整理当前对话仍有效的决定，不以旧实现补充业务前提：

- Service 直接保存可选探测网址及“只能访问这些目标”开关；限制粒度是域名/IP 与有效端口。
  关闭限制时覆盖普通互联网，无网址也可联网；删除独立 Probe、Destinations 和地域分类。

  中继优选；非固定出口按实际目标保留选择，未知目标用默认选择，已有连接保持自己的出口。

### WG 本机端口与职责独立的运行更新

WG 从本机资源输入读取显式 listen_port，公开拨号端口仍来自签名资源，已有 NAT 映射保持独立。
Hy2 的 listen 和成对 TLS 引用保持原规范字节；无当前种类可消费的混合输入严格拒绝。
本轮曾扩展精确 IP 绑定及逐 peer connected UDP，规模审查发现它会叠加全 peer 保活的成本，
且精确 IP 并非本次需求，已在安装、部署前删除实验路径。最终使用一个 WG Device 的原生
共享双栈 UDP，不新增连接池、引用体系、管理对象或协议版本。

本机换端口先确认新权限，再以相同权限应用新端口。失败或回读不确定时清除运行确认，
保留已接受权限、实例和无关 Hy2；原检查重试明确期望端口。实际端口不能由旧 options 值
或仅配置 hash 推断，网络刷新也不能以随机端口掩盖接收绑定失败。DNS 刷新只消费当前已确认
View，WG unknown 时不通过普通 DNS 分支重放旧权限或旧端口。已有恢复器沿既有映射、正常
同步和重载入口执行，并以受保护文件的条件替换保全并发输入。

真实隔离验收还暴露了本机 access 授权与 forward 职责的耦合：撤本机未选中的 Policy 会因
selector 成员引用变化重建仍运行的共享设施，Mixed 校验也误要求其必须供本机 access 使用。
现成员引用从同一权限投影派生，原 CAS 不增加 wire 字段；原生 access 在校验当前 Policy、目标、
入口与出口后查询既有组件。Mixed 独立验证同节点的原生 forward 入口，未增加访问权限。
正式 Run／Store 的隔离回归已验证撤未使用的本机授权、WG 端口占用失败、unknown 及释放后恢复；
同一 TCP、进程与 WG 实例代保持，独立 Hy2 监听可回读，已撤权限未复活。

另修复执行 TCP 半关闭，以及 Hy2 TCP 拒绝错用控制响应编码的问题；后者修前会被原生 TCP

构建及 Go 检查通过。最终工作区 APK 已覆盖安装并逐字核对，受保护密文保持；真机沿普通界面
