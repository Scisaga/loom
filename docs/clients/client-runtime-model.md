# 客户端运行时最小模型

## 当前业务基线与实现差距

业务目标以[服务与策略的当前业务基线](../core/control-model.md#服务与策略的当前业务基线)为准。
客户端当前选择一条互联网 Policy，由它唯一确定 Service；授权可选集合不等于多条策略同时生效。
互联网 Service 保存预期访问服务的探测网址及“是否只能访问这些目标”开关，取消独立 Destinations、
Probe 对象和管理页。国内/国外样本不能推导成地域分类、域名/IP 库或强制直连/代理规则。
LAN 保持独立授权；本次不据互联网选择语义擅自改写 LAN 偏好。

这是目标及迁移要求，不表示当前源码或部署已经完成。旧的按服务 Preference、共享目标池、完整
路径绑定、性能切换关闭连接、等过期才采样及逐 View 重建属于需要替换的实现；不能据其存在限制目标。
原件、身份密钥、high_water/floor、latch 和报告序列保全；规范字段与一次性前向迁移未完成前，
不继续相关配置写入，不修改已签原文或在同一认证前沿改写 View，也不恢复旧运行 fallback。

## 持续分段测量与稳定换路

access 测本机到获准且具有实际资源的入口；forward 测自身后续有向链路；internet_egress 测
出口到 Service 网址。control 验证、汇总并经私有通道批量交付原始样本，不产生授权或健康事实。
相同来源、资源、网络代及执行规格的样本复用；同出口、同 URL、同请求及解析参数只测一次，
不按 Service、Policy 和设备重复展开。没有网址时仍可依靠传输和真实业务观测联网。
每个 internet_egress 都须自行持续覆盖其适用 Service 的全部探测项；是否有 access 正在使用
只影响调度优先级，不能免除检测。access 只测自身到入口，消费共享的链路和出口原样本，并保留
真实业务观测；不再逐个重复请求出口已测的网址，也不轮询完整路径与网址的乘积。

出口 worker 的 HTTPS 请求使用[受信本机物理 I/O](../core/current-contract.md#本机出口测量的物理-io)，
沿同一原生实例的认证 DNS、平台 underlay 绑定和公网地址守卫取得连接，不能进入自身 access
VPN 后误报为本机出口。该入口只供已可应用运行权限的本机消费者使用；普通业务仍在现有
access／receiver 快照校验当前 Policy。互联网共用一个物理出站，不另存每 Service 的目标权限。
独立 LAN 的捕获范围来自完整映射及其 overlay 记录，实际请求再与当前限制目标取交集，拒绝
不能旁路其他 Scope。权限收窄只关闭已失权连接，不因逐 Service 的物理出站或诊断规则变化
替换整个实例。领域、签名 wire、持久身份及 UI 不增加对象，原报告规格与原件保持。

每节点共用请求率、并发、字节和超时预算，在途相同测量合并。活跃业务优先，其余按最久未测
公平轮转；目标增多而预算不变时增加实际覆盖间隔，不延长样本寿命。测量周期、样本有效期和
最小性能换路间隔分别处理，冷却期间继续测量。取消不记失败，重复报告旧样本不算新测量。
原时间、规格、有效期和签名报告来源保持；批量交付及差量缓存可删除，缓存失效重新领取有界
工作集的完整批次，沿不透明 cursor 的非授权提示继续公平轮转。单次响应和累计快照分别守住
字节预算；提交失败保留原请求 base 与 cursor，不在本地裁剪后继续使用旧 cursor。缺项保持
unknown，不能把一页样本冒称全范围测量；详见[批量差量交付契约](../core/current-contract.md#设备相关测量的批量差量交付)。

access 选合格入口，forward 在同一 Policy、最终出口约束内为新连接选下一跳。资格取决于职责、
资源和权限，不能用 control 身份替代转发能力；不得预固定中继。可比较的分段 RTT 构建有向图，
固定出口共用到该出口的反向计算结果，忽略探测目标差异，不生成按网址区分的入口或中继选择；
出口网址观测仅用于相应业务诊断。非固定出口才结合目标相关的出口观测为连接选择出口。
未知边不补零，HTTPS 总耗时不当 RTT 相加。不展开设备、Service、Policy、完整路径和网址的
全量乘积扫描。
逐跳上下文已获用户批准，保持 schema 3：传输认证实际发送节点，连接显式携带 Policy（唯一确定 Service）、原始来源、
固定最终出口和已走节点。WG 使用自身可靠执行流，Hy2 使用自身原生请求扩展；共同校验实际
前驱、来源当前授权、出口资格、路径约束和防环。字段与迁移边界见现行契约，真实验收见交付对账。

冷启动和切网并发探索，先使用实际可用路径联网，不等全部网址完成。性能优化须满足最小间隔、
显著改善及持续性，新连接采用优选，旧连接保持；实际故障、撤权和用户操作按其原因处理，不受
性能冷却限制。样本过期不等于连接故障，单网址失败不等于整网不可用。确需立即改用新路径时，
可重建该服务连接，不停止整个 VPN；TCP 长连接不承诺无损迁移。

测量完成即按小批次交付新增原样本，不等最慢任务或整轮截止；仍在执行的其他任务继续共享原预算。
同一调用串行消费完成批次，缓冲受并发数限制，不为每次完成复制、验签或重新投影全部授权。
运行端合并增量后按既有规则重选，首次可用证据立即生效；稳定性能改善仍须满足原切换条件。
domain、wire 与 persistent 没有新增实体或字段：交付的仍是原 Observation，原时间和截止不变；
runtime 只增加本次可取消调用的完成通知，UI 从实际应用回读更新。停止、切网、配置或用户选择
替换本次输入时取消实际 I/O；提交前核对身份、当前授权、Preference、网络代与运行实例。
合并先按完整测量规格去重并排除旧网络代；同一资源在互联网与独立 LAN 的不同 Policy 下可有
不同准入规格，缓存和回读不能只按 ResourceID 合并或拒绝这些原样本。
通知失败取消剩余任务并等待退出，不把取消或未交付结果记作网络失败，不产生迟到回调。
Android 纯选路桥以整数毫秒接收调用方当前时间，与原样本精度一致；不能截到整秒后将刚完成
的样本当作未来数据。该参数只是本机执行输入，不改变签名 wire 或持久格式。
Android 切网后立即启动新代的测量循环，用户改变 Policy 后立即探索该 Policy 的入口；二者
不等待旧周期唤醒。测量 I/O 仍在操作锁外，性能优化继续遵守原门槛及最小间隔。
Android 桥的异步请求必须在构造调用返回前取得延后使用的输入所有权。JNI 的字节数组借用只在
本次桥调用内有效；立即解码为拥有自身数据的领域值，或对需要延后解析的有界字节输入复制一次，
不能让请求闭包保留借用切片。副本只属于本次可取消调用，不进入持久状态；取消与退出仍按上述
规则等待实际 I/O 和回调结束。此边界不改变领域、wire、授权、测量预算或 UI，也不为读取失败续期旧样本。
最小验证覆盖快入口先用于真实业务而慢任务尚未退出、取消及通知失败后无迟到结果、共享测量
保留同一原时间、构造返回后原输入被覆盖仍消费原快照，以及旧运行／网络／策略结果不能覆盖新选择。没有分段计时，不把整轮等待
直接认定为此前十秒以上交互的原因。

多个网址必须分别保留结果，不能先平均后丢掉目标和测量位置。非固定出口的目标选择粒度为原始
域名/IP＋端口；同一连接及其多路复用请求使用同一出口。未知目标用默认优选。固定出口时，
网址观测既不改变出口，也不参与入口/中继排序，不保留先前助手提出的目标专属校准例外。

非固定出口的目标恢复采用用户已确认的[后台 TCP 试连](../core/current-contract.md#后台-tcp-恢复校准)：
近期真实目标缺少恢复证据，且可比的新分段测量形成持续明显改善后，按节点原预算公平校准必要
备选。已有相关共享结果优先复用。后台试连不改变生产 selector，不产生真实使用活动，不发送
应用请求；取得证据且性能条件满足后才更新新连接，已有连接保持。过期不当故障，也不能让
旧目标覆盖永久阻止恢复；校准来源与普通 TCP 分开，不成为新的授权、探测对象或持久状态。

用户已确认：非固定出口的未测目标默认优先已测可达覆盖，同等覆盖再比分段代价。连接目标按
规范域名/IP＋有效端口去重，避免同一站点的多个 URL 重复抬高覆盖权重。同目标任一新鲜成功
形成成功证据，全部配置 URL 均有新鲜失败才为失败；部分缺席、过期和冲突为 unknown。
不按完整路径重复计算出口覆盖，不把 unknown 当失败，不把探测网址当普通互联网访问白名单。

执行器先过滤当前 Policy、资格与当前规格，真实首跳/有向链路失败只影响依赖它的候选；网址
失败只影响相应目标证据。固定出口只比较传输段；非固定出口先提出默认优选，再按连接目标
选择出口并复用到该出口的入口/中继估计。未测段不补零，HTTPS 总耗时不作为 RTT 相加。
证据相同且没有可比改善时保持当前选择；冷启动在未知候选中选择可尝试项，继续并发探索。

合法执行资格与诊断结果分开。Policy、职责、资源、认证材料、当前规格及合法拓扑决定可尝试
集合；一次准入回显或链路回显失败只形成该测量动作的负面证据，不从此集合删除路径。有
合格且无相应负面诊断的备选时，新连接可以避开失败诊断所依赖的路径；没有备选时，保留
仍合法的当前路径供真实业务拨号。冷启动或全部诊断失败时，从合法集合稳定选择可尝试项，
继续预算内探索；只有资格失效或确实无合法拓扑才生成阻断。图计算也不能用诊断失败剪掉
全部合法后继，再把它误报为拓扑无路。样本、原有效期和失败事实不改写，保留路径不制造
available，实际建连仍经过原生准入、完整 CAS 及逐连接授权校验。

较新的真实 TCP 成功可反证其明确经历的本机首跳传输负面证据，须匹配 Policy、候选、执行
规格及来源网络代，且成功仍新鲜、本次实际拨号开始时刻严格晚于该失败。原生 TCP 事件已
记录开始及结束的整数毫秒；由同一事件两值差形成的 MetricMillis 可以无损还原其开始毫秒。
同毫秒或较早开始、较晚完成的请求不反证；缺少可靠开始绑定时不能靠完成时刻减另一段耗时
推造该证据。该规则也用于固定出口的传输估计；
不把 TCP 成功当作 HTTPS 成功或准入回显成功，不增加网址覆盖，也不能凭逐跳自由选路的
候选名称反证未记录实际经过的远端 Link。实际业务的目标失败仍按目标处理，恢复候选仍
遵守既有后台校准及稳定换路条件；撤权、资源失格和用户操作的处理不变。以上仅修正运行
投影，不增加 domain、签名 wire、持久字段、计时器或管理对象；UI 同时保留实际选择和原
测量结果，不能把“正在尝试”展示成业务健康。

性能切换用可删除的运行内存记录最近实际应用与待确认改善，按本机单调时钟计算间隔，不新增
持久偏好或授权字段。初始执行参数为最小间隔 30 秒、RTT 同时改善至少 10% 与 5 毫秒、至少
两轮不同原采样确认。样本是否可用只按其原有效期、来源网络代及完整测量规格判断，不再叠加
另一份性能有效期或要求分段样本在同一时间窗口成对完成。当前样本缺席时，
覆盖改善也须由备选持续的新鲜成功证明更多已测覆盖，不能把当前未知项标成失败。重复报告不能增加确认
次数；冷却期间继续测量。真实故障、授权撤回、用户主动选择与首次取得可用入口即时处理。
这些是待真机校准的本地执行参数，不是用户授权或生产性能结论。

同一 Policy、来源网络代及 scope/目标内，“已经取得过可用入口”的既有运行记忆随合法候选
切换保留。故障后改用未知备选，不能把原路径的恢复误当首次发现并绕过性能间隔和持续
确认；新目标以及 Policy／网络代变化仍按原规则重新建立记忆。该标记不表示当前路径健康，
也不由未确认的 selector 操作确立；pending 与实际应用时间仍按各自原语义处理。

测量继续由同一节点调度器异步完成。首次发现满足改善门槛的合法备选后，现有待确认记录只向
调度器提示当前路径与该备选所需的本机测量项；这些项暂用活跃周期，与其他活跃业务共用原
请求率、并发、字节及超时预算，未测最久的其他项仍公平轮转。没有独立成对复测流程，不等待
全部候选或远端来源同时完成，不替其他节点测它们负责的段。

每项完成仍立即交付：冷启动、真实故障及撤权及时处理；性能确认只在全部相关差异项都产生了
相对于各自上次确认原件的新样本时累加，不用某个来源的最新时间阻塞其他来源。仅一侧更新或重复交付不增加确认，仍有效的另一侧样本也不会仅因
时间错开被当作反证。明确不再改善、候选撤回、规格或网络代变化，以及原证据失效时清除相应
待确认记录；已建立连接不因此关闭。预算不足只延后测量，不延长旧样本的截止时间。

这项修改的 domain、签名 wire 与持久身份均不变。调度优先级由运行内存中的实际选择和待确认
备选单向派生，Android 的本机调用只传递这份已有内存；Linux forward 将其映射为本节点发出
的有向 Link，access 只映射自身首跳。优先级不是健康事实，不进入 View、报告或 Preference，
不新增 UI 管理项。可删除内存丢失后从普通异步测量重新建立确认。
多个目标共用一份测量项进度表，只保存各项原采样时间和本机处理位置；每个待确认比较只保存
规格指纹与已确认位置，不复制完整路径样本。本机处理位置不排序签名事实，不进入报告序列，
也不成为控制权威或持久值。

selector 的一次更新包含默认候选与目标覆盖表，二者必须属于同一当前 Policy，并带上计算前
读到的完整默认候选、目标覆盖表及运行期快照标识作为并发比较条件。条件变化则丢弃过时优化并重读，不关闭新选择的连接。应用
成功并读回完整默认、覆盖表和本次更新的快照标识后才记录换路时刻；A→B→A 或同值重设也使旧计划失效。
每次更新使用新的不可预测标识，跨原生实例也不复用。该标识只属于运行快照，不进入身份、Preference、授权 View 或报告序列；性能更新只影响新 TCP 连接与新 UDP 会话。

最小测试覆盖固定出口忽略网址差异、非固定出口覆盖优先及同覆盖成本比较、无/部分/过期样本、
同目标多 URL 不重复计权、目标分别选择且未知目标用默认、重复原件不能确认改善、三个时间
独立、切网/撤权/真实故障绕过性能冷却，以及过时更新不覆盖用户选择或关闭其连接。
异步回归还须覆盖分批完成与相差超过旧时间窗口的有效样本、单侧或重放不重复确认、原截止
失效、待确认备选只在同 Policy／网络代下提高优先级，以及受限预算中其他项仍获得测量机会。

测量去重减少重复需求，预算限制实际操作量，CRDT/报告差量减少重复传播；三者分别解决不同成本。
若一个节点当前有 W 个独立待更新测量项、有效执行能力为每秒 b 项，则完整覆盖间隔至少为 W/b；
不能通过重复报告或修改有效期掩盖覆盖不足。当前路径、必要备选与恢复探索共享预算，其余公平
轮转。即使当前没有消费者，出口仍公平覆盖适用的探测项；预算不足时增加轮转间隔，不续期旧样本。

相同约束下到出口的距离可复用，不按每个 URL 重跑整张图；非固定出口按需比较对应出口代价，
不为所有完整路径建立测量项。接收端相关授权仍独立校验，复用计算与测量不合并权限。
已认证的新报告到达后，在既有报告存储上增量更新可删除的测量索引，再向客户端按当前相关范围
批量交付变化。只有输出是差量而每次仍全量投影、重验所有来源和复制样本，不算完成规模优化。
出口原样本通过既有成员报告差量同步在 control 间传播，access 和 forward 批量消费相关变化，
同一出口检测一次的结果须可供全网相应消费者复用。客户端不以重新执行整套网址检测来确认收到
的出口样本；本机到入口的可达性仍须在本机测量。

本文定义现行 Android / Linux / Windows 客户端运行时模型。它是实现、持久化、wire、
运行时和 UI 的共同契约；读者不需要阅读代码才能判断一个行为是否符合设计。

这里的“同构”不是要求各层拥有相同结构体，而是要求同一个事实只有一个来源，
各层使用稳定标识保持其身份和语义。安全脱敏与纯派生允许字段变少，但不得在另一层
制造第二份可独立修改的事实。

本文只使用八个核心概念。它们是职责边界，**不要求一个概念对应一个类型、表或服务**；
能够用值、纯函数或现有安全存储表达时，不新增实体。

签名 View 只交付稳定授权、资源及必要身份材料，不交付预展开候选、完整运行 JSON 或逐路径 ACL。
本机只为当前互联网 Policy 与独立 LAN 选择派生接入候选；资源 transport 与 Policy／出口选择解耦。
forward／internet_egress 由相同事实派生本位置执行，逐连接校验显式 Policy、原始来源、最终出口
和已走节点。源节点认证不授予业务权限；完整契约与迁移见[稳定 View 与本机运行派生](../core/current-contract.md#稳定-view-与本机运行派生)。

## 八个概念

| 概念 | 唯一职责 | 不是 |
|---|---|---|
| `DeviceIdentity` | 标识设备、保存已认证的 `ControlConfig` 成员链信任绑定、已见事实前沿与不可回退 floor，并对私有请求签名 | 路由状态、网络测量或拓扑副本 |
| `CertifiedLKG` | 最近一次通过认证并原子保存、由有效 control 签名的完整设备视图；决定离线可使用的授权范围 | 宿主应用成功、全网最新状态或当前网络是否可用的声明 |
| `RouteCandidate` | 描述某一 Service 范围内从本机到目标的一条允许路径及其最终出口 | 节点类型、健康状态或平台进程 |
| `RuntimeCandidate` | 将一条 `RouteCandidate` 化为宿主可执行且可稳定识别的运行描述 | 第二份拓扑、独立配置源或健康注册表 |
| `Observation` | 记录特定底层网络代中实际 transport / business outcome 及有限提示 | 授权、期望状态或为了填满评分而生成的样本 |
| `Preference` | 保存当前一条互联网 Policy 与各独立 LAN 的选择或待选意图 | 对当前可用性的断言 |
| `Selection` | 记录宿主 selector 回读确认的当前实际选择 | 仅由决策函数算出的期望值 |
| `HostAdapter` | 连接纯核心与 Android / Linux / Windows 的安全存储、VPN、transport 和 selector | 平台各自实现的一套选路规则 |

八者的关系只有一条主线：

```text
DeviceIdentity 绑定 CertifiedLKG
        │
        └─→ 纯函数派生 RouteCandidate
                    │
                    └─→ 纯函数生成 RuntimeCandidate
                                  │
Preference + Observation ────────┴─→ 纯函数提出候选
                                              │
                                      HostAdapter 应用并回读
                                              │
                                          Selection
```

`CertifiedLKG` 决定“允许做什么”，`Observation` 说明“此刻实际发生了什么”，
`Preference` 说明“用户想要什么”。三者不得互相代替。

## 路径语义

`Service` 定义目标地址或名称范围；每条 `NetworkPolicy` 固定属于一个 Service，定义显式允许
和路径限制。设备的 `DeviceAuthorization.PolicyIDs` 授权可选策略集合，同服务可以有多条；
客户端保存当前一条互联网 Policy 的选择，由它确定 Service；仅在该策略内选路。未授权、历史 deny、
已删除或冲突的策略不产生候选、ACL、凭据或探测授权；待选服务保留默认拒绝的 selector。
Loom 管理的请求命中上述目标时须拒绝，不能因没有候选就回退 Direct、换用较宽服务或绕过捕获。
客户端只消费签名 DeviceView 下发的交集，不从入口存在、DNS 解析或探测结果创造新授权。
互联网 Service 的终点是指定或可选的最终出网节点；`local_network` Service 的终点是固定的
`forward` 网关，不称为互联网出口。策略创建后不能改属其他 Service。

### Direct 不等于一跳直达

- **普通 Direct** 的 `final_exit=direct` 且受管节点链为空：本机不以任何受管出口身份，直接访问目标地址。
- **一跳直达** 的受管节点链包含一台具有 `internet_egress` 职责的节点：客户端经获授权的
  WG、hy2 等共享数据入口到该节点，再从它访问互联网目标。
- **中继路径** 至少包含入口转发节点和最终出网节点：客户端接入首跳，再沿有效节点职责与
  资源自动派生的中继段到最终出口。每段引用确定的 `LinkID`，不要求管理员配置节点对。

因此，以下是三条不同的 `RouteCandidate`：

```text
Direct:                    device → target
一跳直达 demo-sv:          device → demo-sv → target
同出口中继 demo-sv:        device → demo-cn → demo-sv → target
```

后两条拥有相同的最终出口，但拥有不同的入口和受管节点链。在策略同时允许这两种入口时，须同时保留为候选，
使“一跳直达失败后仍从同一最终出口经境内中继访问”成为普通选路结果，而不是专用分支。

`public_data_ingress` 是可供客户端使用的一种已认证首跳声明；已有 WG、hy2 等共享
`TransportResource` 也可成为首跳。首跳由 Service、Policy、设备授权与资源共同投影，
不要求为每个设备新建接口或 `NetworkLink`。入口声明绝不表示该入口在当前网络可达。入口可能今天可用、
随后因 UDP 受限而不可用、几天后再次恢复，整个过程都不需要修改认证拓扑。

Policy 的业务入口、中间转发及互联网出口分别使用规范范围 `any / only / none`。
any 表示所有符合资格的当前及未来节点；only 只允许非空的明确 ID 集合；none 不允许此位置的节点。
范围模式缺失或仅有空数组不是 any，须在认证输入处拒绝。only 的节点失效后保留限制并移除相关候选，
不自动变为 any。第一台受管节点须满足入口范围、有效资源及职责；中间节点须满足转发范围和派生
中继方向；最终节点须满足出口或固定 LAN 网关约束。一跳互联网候选的节点同时满足入口与出口范围。
中间范围 none 仍可允许一跳，入口 none 则不产生经网络接入受管节点的路径。

普通 Direct 独立由 `allow_direct` 控制，不经过受管首跳或出口。Direct 允许加出口 only 表示两种
路径都允许；要求只经指定出口时必须关闭 Direct。没有设备限定本地出网许可时，纯 Direct 可用入口 none 表达，不能把旧空入口
集合重解释为不限。LAN Policy 新写入固定 allow，只含入口及转发范围，没有互联网 Direct/出口字段，
入口选择只能改变到固定网关的路径。这些检查均从所选 PolicyIDs 解析，不新增本机授权策略。

中继段 From/To 表示业务方向，WG 两端均配置对端已认证拨号坐标并允许建立同一会话。
规范形状中的 initiator_node_id 是确定性默认坐标，不限制实际拨号端；不恢复旧 direction/reverse_only
配置或人工邻接。授权、业务方向和实时可达性是不同事实。

`NetworkPolicy.allow_direct` 表示选择该 Policy 的 access 才可为其固定的互联网 Service 产生 `final_exit=direct` 的普通 Direct
候选。它不能表达“只有某个 hybrid access 在本机充当该 policy 的固定出口”。后一语义由规范排序的
`local_egress_devices` 表达：成员必须是该 policy 的获准最终出口、具备 `access` 与 `internet_egress`
能力；只有授权设备 ID 命中时才生成受管节点链为空、`final_exit` 为该设备稳定 NodeID 的本地出口
候选。空链表示本机执行、不经网络隧道，不能抹去逻辑最终出口身份。候选 ID 同样绑定该 NodeID；
其他设备仍把该节点当作一跳或中继出口。普通 Direct 与设备限定本地出网的授权来源不同，不能在
导入时把设备级许可提升成全 policy 的 `allow_direct`。当前所选 Policy 允许本机作为最终出口时可选择该本地候选；普通 Direct 候选仍由该策略的
`allow_direct` 独立决定，不通过全局模式过滤。
本地出网没有业务首跳，不套用入口范围，也不要求回拨本机或提供入站资源。

`TransportResource` 保存稳定 ID、承载节点、interface/listener、拨号坐标和公开认证参数。
节点职责与 Service/Policy 决定使用资格，不能通过资源名称或 control 身份推定业务权限。
公开首跳分别检查 access_enabled/link_only；后续 WG 与 Hy2 均为独立原生段，不要求发送者拥有公开监听。
有向邻接由来源 forward、接收者 forward/internet_egress 和接收资源确定性派生；没有人工 Link 权威。
来源稳定身份、接收资源及来源解析参数决定测量规格，规则见[中继段映射](../core/control-model.md)。

WG 来源只使用节点授权登记的公钥；自身与其他节点投影口径相同。固定私钥即使没有接收
资源也从原文件核对后用于发送，派生私钥仅在公钥与登记值匹配时消费。共享 endpoint 固定为
`wg-shared`，接收资源增删不改变其身份。缺少登记值不生成 WG 候选或有向段，不能隐式换键；
独立 Hy2／Direct 不从 WG 登记状态取得或丢失权限。已有连接的连续性仍须单独验证。

候选由设备从同一已认证 View 与当前 Preference 本机派生，只覆盖当前互联网 Policy 和独立 LAN
选择。control 不提前展开全部可选 Policy 的入口×出口组合，也不交付完整路径或运行 JSON。
一个候选绑定允许的入口、首跳资源和最终出口；节点图只提供后续可行性约束。
access 选择入口，forward 根据自己的有向链路和共享观测继续选择下一跳；已走节点、剩余跳数及
当前 Policy／最终出口始终限制每一步。无样本段不能按零成本加入测得代价，仍保留有界探索机会。

固定出口共用到该出口的图结果，网址差异不产生目标专属入口。非固定出口按目标保留出口选择；
无该目标样本时，先比较当前 Service 网址的有效已测覆盖，同等覆盖再比较分段代价。
地理信息仅能安排未测入口的探索顺序，不能替代真实测量。完整 HTTPS 耗时不直接与段 RTT 相加，
跳数和 ID 只用于无样本尝试及确定性平局；少跳不制造可用事实。

### 候选身份

`RouteCandidate.ID` 绑定 ServiceID、PolicyID、EntryNodeID、FirstResourceID 和 FinalExit。
forward 改变后续中继见证不改变入口／出口候选身份，也不轮换传输凭据。不同首跳 WG/Hy2 资源
具有不同身份和观测。Direct 的入口／资源为空且最终出口为 direct；获准本机出网保留本机最终
NodeID，不能因未经过网络首跳就提升成全 Policy 的 Direct 许可。

候选、图、RuntimeProfile 与底层 JSON 都是可删除运行投影，不属于签名 View 或持久身份。
同一资源的 transport 按资源复用，候选不再逐一创建同名 outbound。单一接入 selector 的完整
快照包含 PolicyID、默认候选、按目标覆盖、所引用候选的入口／资源／出口值及 CAS 修订标识。
原生入口重算候选身份并验证它属于当前 Policy，不能只核对一个字符串 ID。每条连接建立时固定
自己的上下文，性能选择更新只影响新连接；已有 TCP 不能承诺无损迁移。

TCP 建连结果须沿[逐跳确认](../core/current-contract.md#逐跳-tcp-建连确认)返回：原生 WG／Hy2
不能只写完请求便向上游确认成功。等待的是下游建连响应头，不等待应用首包；拒绝、路径不可用、
取消和应用失败分别保留其范围。该修正不增加主动探测，也不以关闭共享传输处理单连接取消。

三端先验证和原子保存授权／认证进度，再派生及应用运行值。执行失败不撤销已加入身份、不
降低 floor，也不把旧运行重新当当前授权。权限变化能沿当前原生实例差量应用且确认时，保留
仍获授权的流；新流与撤权登记共用校验边界。监听、密钥、传输设施、DNS 或捕获输入变化不能
冒充权限差量。局部应用或回读失败不得恢复旧权限；正式运行验收仍须按平台逐项完成。

### 常驻数据面与增量应用

本机 access 的可选 Policy 与本节点 forward 职责分别校验。撤掉本机未选中的 Policy，不能
要求删除仍为其他来源执行的共享 Policy 或重建其转发、出口设施。source selector 的成员表
只是当前权限投影中既有组件引用的确定性结果，不是另一份授权；增减引用而实际组件未变时
沿同一权限 CAS 应用。每个新连接先校验当前 Policy、目标及入口／出口，再取得实际已运行组件。
已撤权限的连接关闭，其他连接保留；Mixed 捕获校验也不能把 forward 入口限定为本机 access 的成员。

运行会话中的网络栈、WG 设备和可复用 Hy2 传输不随 View 或性能推荐一起替换。连接建立时
读取当前授权及选择，持有实际连接对象；后续性能更新只替换新连接读取的选择快照。forward
同样在每条连接建立时选择下一跳，保持 Policy、最终出口和已走链校验。无需再持久化旧路径
或建立连接迁移管理器，WG 与 Hy2 仍各自独立终止和承载业务。

forward 的本地遍历投影只排序已准入连接的后续段。原始来源和首跳范围仍由 source 及每个
receiver 的当前完整权限校验；未被后续选路消费的首跳范围不参与静态设施变化判定。现行原生
遍历语法要求该字段时，运行投影使用中性值，不能将它作为准入授权。签名 View 和接收权限
保留真实值：扩大入口范围保留仍合法的连接，收窄时只关闭完整路径已不合法的连接。
本机是否可作首跳／中继不决定既有传输设施是否存在；节点仍可作为另一合法路径的最终出口。
设施保留后，优化及活跃测量优先仍按原 View 的入口／中继范围判断本机位置，不读取中性遍历字段。
共享链路测量继续按来源与完整规格复用，不因保留设施增加逐 Policy 探测任务。
后续遍历图、forward 容器和发送资源集合由既有本机资源池增量消费，见[发送资源的按需增量应用](../core/current-contract.md#发送资源的按需增量应用)。真正接收 listener、捕获、认证 DNS 或物理出站设施变化仍须分别判断，不能只因 View 不同就替换实例，也不能将所有变化一律当作资源池更新。

闲置纯发送 WG peer 按用户选定方案在最后实际引用退出后完全回收；当前路径、合法旧连接、
在途拨号和测量继续持有原对象。接收准入或管理仍需要的 peer 保留，发送保活由实际发送需求
单独决定；不把“无发送”推成撤销接收资格。回收不更换身份或重启共享设备，再用时依当前
授权冷建；旧清理不得影响同公钥的新对象。此目标尚须实际制品与运行验收，不能把关保活当作
完整回收已经实现。

| 层 | 对应关系 |
|---|---|
| domain / signed wire | 现有设备、Service、Policy、资源和授权不变；测量和推荐不写入 View |
| persistent | 保留唯一身份、LKG、原密钥与认证进度；不保存另一份期望运行状态 |
| local runtime API | 对当前已认证投影按 peer、准入和权限生成语义差量，CAS 应用并回读；未变化字段不重复下发 |
| runtime | 复用已存在的设备、peer、socket 和业务连接；新增设备只增加必要准入，撤权只影响失去权限的连接 |
| UI / report | 既有选择、应用结果与实际连接回读继续使用；不新增管理页或运行权威 |

后台配置领取只负责认证、耐久接受和通知，不预先关闭整个运行代。接受变化后取消正在等待的
测量工作，使运行主循环及时应用权限与 peer 差量；取消不生成失败观测。应用主循环也在每轮
工作开始前核对当前 LKG，覆盖通知早于测量注册的竞态。认证或持久化失败仍立即停止；局部
应用错误不能被测量取消吞掉，也不能因此恢复旧授权。测量和业务连接不共享关闭生命周期。

WG peer 的地址、keepalive、精确 AllowedIPs 可在原设备内更新；未变化的 endpoint 不重写，
避免覆盖协议已学习的可达地址。删除 peer 或修改握手秘密只影响该 peer，不重建整台设备。
未变化的域名解析缓存复用；改名、删除和并发迟到解析不得复活旧坐标或刷新旧样本。
普通 WG 资源和 relay 边不自动生成宿主接口、管理地址、HostSources 或返回路由，也不授予任意宿主管理访问。既有 underlay SSH／WG／LAN、Endpoint、DNS 和代理保持原路径；业务差量不能改变其 route/rule、接口或 DNS。
监听、密钥、网络栈地址、DNS 或捕获确有变化时，按该组件的实际能力和所有权单独处理，不能
把它伪装成权限更新，也不能把“配置不同”直接等同于必须关闭整个 VPN。

最小验证使用用户态 WG 与回环 UDP，不创建宿主 TUN：持续 TCP 在新增其他 peer、权限表更新
和同一认证 peer 改址后继续收发，设备与未变 peer 会话保持；撤销另一 peer 不影响原连接；
迟到解析、重叠来源、过时 CAS 和 host 管理所有权变动拒绝。另须沿客户端正常配置同步入口
验证局部应用及回读；这些隔离结果不能抵扣 Android 真机、切网或生产验收。

普通互联网正向验收不能借用本来被拒绝的文档地址，也不能放宽访问边界。用户已允许本工作项
在独立 user/network namespace、仅有 loopback 且无外部路由时，临时生成公网范围合成地址；
实际值只进入私有证据。正常代理入口须验证无探测网址时的 IP、不同业务域名、认证 DNS、
配置更新前后的持续连接与新请求，仍不把隔离结果当作真实公网或真机终验。

渲染与候选生成均确定性排序，不读时钟、随机数或观测；测量与性能内存由调用方另行提供。
Windows、Android 和 Linux 使用相同候选身份及连接校验，HostAdapter 只派生平台捕获和执行输入。
不恢复签名 RuntimeProfile、逐路径 ACL、完整路径凭据或旧协议运行 fallback。

Windows 的运行构造入口直接接收当前认证 View、瞬时本机 API secret、捕获形态以及已经回读的
网站地址和本机连接前缀，不接收另一份业务 JSON。它使用共享渲染器和 DNS／LAN 投影，只添加
既定 Mixed／TUN 捕获设施。返回值是不可由包外任意 JSON 构造的临时运行投影；监督器消费
同一值并调用精确原生程序检查，不在 Windows 再定义 Service、Policy、WG 或 Hy2 的配置解码器。
该值不持久化、不签名、不反向生成授权；清除后只能由当前 View 重新构造。配置复制供 selector
与局部更新使用，不能借此改变监督器收到的初始值。缓存的绝对路径只在监督器的受保护目录内绑定。
最小验证覆盖三种捕获形态、当前 WG／Hy2 原生配置、认证 DNS、独立 LAN 限制、无选择时拒绝、
正常监督及明文配置回收；旧业务 DTO 与能接受任意业务 JSON 的构造入口一起删除。

## Observation 与可用性

普通本机 TCP 反馈按[本机消费契约](../core/current-contract.md#普通-tcp-结果的本机消费)从真实拨号
结果取得，以现有选择 revision 绑定网络及执行规格，仅在 RAM 消费。它与共享的出口网址、首跳
及有向链路样本分开，不扩大签名 Observation 的动作或访问权限。TCP 目标覆盖带网络前缀，UDP
不消费 TCP 结果；TCP 建连、HTTPS 成功和普通互联网整体状态不得混称。

三端从原设备认证入口取得当前 View 范围内的中继段原始观测，临时保存于同一运行代的 RAM；响应绑定
network、接收设备与 View 摘要，每项保留报告来源、序列、摘要、原样本和当前截止。客户端选择调用同一
`SelectWithLinks`，按候选的精确中继依赖消费这些样本，不持久化为授权、不替远端重新报告。网络读取
失败不产生新样本、不改变结果或延长截止；已有 RAM 样本只有仍适用且未过期时才可继续消费，
缓存可随时删除重建，丢弃不能生成失败或成功。Linux 当前失败时丢弃本次范围，Windows 和 Android
保留至原截止，各端都只消费与当前已接受并运行的 View、接收设备、Link/spec、来源及目标/动作
相符的有效证据。成功的新交付整体替换原范围，空集合也一样，不能用旧样本回填缺项；接受撤权、
资源/spec 变化、换 View 或停止后丢弃，重启先为 unknown。Android 桥返回原规范
响应，Kotlin 只保存当前运行 profile 的 View 绑定；Windows 同一 generation 在原 State 中保存和刷新。
网络 I/O 不占用 Android 的运行/路由锁，迟到结果须再次核对身份、View 和运行代。

已应用的本机运行还可复用原带认证的诊断入口，对当前 Service 的一个必要备选候选执行真实 HTTPS；
它不切换生产 selector，不产生第二 WG 会话。成功、失败及原有效期仍进入原业务 Observation，经同一
选择函数决定下一条实际路径；取消不补失败。Windows 使用共用 adapter，Android 桥消费同一候选投影
与采样函数，再将原业务样本交回当前运行代，持久化前比较并发采样输入，不能覆盖较新的本机结果。
domain、schema 3 wire 和身份保持；RAM 远端观测为可删除投影，业务样本仍为原诊断缓存和报告。

每条 `Observation` 绑定真实来源的网络代、实际目标及动作、观测层、规格、结果、可比较指标和
原采样／有效期。resource 样本绑定当前 Policy 的首跳准入规格，link 绑定有向 LinkID 和规格，
egress 绑定出口的共享请求规格，少量 service 校准才绑定当前候选。不能要求共享出口样本再
展开 Service、Policy 或设备，也不能把中继见证当候选身份。规范输入变化只使相关样本失效。
时间由调用方传入；纯核心不自行读取时钟。

对当前网络代，一个候选只有三种运行状态：

| 状态 | 含义 |
|---|---|
| `available` | 对该候选执行的真实 transport 建连或正常业务已经成功；成功范围必须如实保留 |
| `unavailable` | 对该候选执行的真实 transport 建连或正常业务已经失败，且结果仍有效 |
| `unknown` | 没有结果、结果属于其他网络代、已经过期、无效，或结果范围不足以证明可用 |

一次入口 transport 成功只能证明对应入口成功，不能伪装成未实际执行的端到端业务成功；
一次完整业务成功则可以证明当时整条候选可用。客户端可以复用认证的中继段观测，
但不得为了把所有候选变绿而逐条扫描完整业务路径。
因此 transport/link 与 Service business 是两种显式观测范围：前者可为 `available`，同一候选的
Service business 仍为 `unknown`，直到对该 Service 匹配的真实目标或正常业务动作成功。
Auto 可以用已知首跳连通性优先尝试候选，但不能据此向 UI 或报告宣称该 Service 已健康。

完整业务探测保留认证 HTTPS 目标的原域名，沿当前候选执行，由最终出口使用自己的认证解析器解析；
Direct 由本机解析。不先用客户端解析器生成目标 IP，也不把未单独检查的 UDP/DNS 宣称为成功。
解析器与 HTTPS 目标都来自相应执行设备的认证 `DeviceView`。解析器来自设备授权中的
规范解析器集合，首次加入可由 Invite 的认证配置取得；HTTPS 目标直接来自当前 Policy 所属
Service 的网址集合，不从独立目标池按 matcher 拼接。限制开关关闭时，这些网址仅为测量样本，
不构成普通互联网白名单；开启时按同一声明派生访问边界。相同物理测量可以共享，业务结论仍
须对应来源、网络代、目标、执行规格与真实范围；无网址保持主动业务证据 unknown，不阻止联网。
探测沿获准传输执行，不能借宿主 resolver、系统 fallback 或扩大 ACL 修通。中继 Link 的原生
传输检查与出口网址请求分别保留，不从其中一种推断另一种成功。

目标可达性必须结合实际路径的最终出口解释。操作者已确认当前网络中境内出口不能访问部分境外
测试目标；这类失败只证明该路径到该目标不可达，不证明入口节点、WG 中继或其他 Service 故障。
境内接入后经中继从境外出口访问，与境内直接出网是不同候选。验收应沿各自必须完成的业务链
选择目标，不能要求境内直出通过境外目标，也不能通过更换成境内测试目标宣称境外业务成功。
同一 Service 的多目标处理不得以跨目标成功数量、首个目标或任一目标失败决定节点整体健康；
必须保留目标与候选的对应及实际结果。地域本身不新增权限或静态健康标签，实际授权仍来自 Policy，
可达性仍来自相应路径上的业务观测。

`BootstrapCapability` 只授权首次 claim/resume，不因设备已完成加入而继续授权配置或报告。加入后
设备凭本机身份和签名，经有效 control 的设备认证私有入口领取当前签名 View，并上报运行事实；
配置、报告和 control 同步可使用已有共享 `TransportResource`，**不要求专门的 `NetworkLink`**。
某个数据入口或中继链路失效只影响引用它的候选；设备仍可经独立认证管理入口
领取修复 View，缺失业务探测保持 `unknown`。私有入口可达本身不证明业务 `available`。
共享承载上的各项服务仍分别校验 Device tunnel 的 TLS/SPKI 与设备身份；载体握手不能替代私有服务认证。
链路资源或 `EndpointGeneration` 的拨号主机名只用 View 中认证的 DNS 解析，解析结果只作本次拨号地址，
不能改写认证的 server name、SPKI 或稳定节点身份。
DNS overlay 只接受精确 `.loom` A/AAAA 映射，`control.loom` 由已认证 control 的私有 Web 入口投影。
解析结果不能扩大 Service/Policy ACL；在同一网络代内 DNS 映射改变，依赖该名称的旧连接与业务观测
失效并重新解析。Loom 名称的解析不能反过来依赖尚未建立的自身 tunnel，亦不得把 `.loom` 规则
安装为开发宿主初始 namespace 的全局 DNS 接管。
尚未取得 View 的首次 bootstrap 使用只含短凭据与固定 TLS 坐标的 InvitationReference；具名入口只解析
这一 underlay host，使用内置 DoH 预设且精确核对名称、SPKI 和叶证书摘要。同事务恢复复用原身份、request ID 与引用；
绑定后的原签名 Invite 仅经私有认证交付，验证后替换引用。取得 View 后改用当前 View 的认证解析器；
两条连接共用平台 socket 保护，Android 活跃 VPN 的 bootstrap DoH 同样使用受保护 underlay socket。
Android HostAdapter 在本机执行投影启用 libbox 的平台接口控制，使其 TCP/UDP underlay socket 实际调用
`VpnService.protect`，否则隧道自身会重新进入 VPN。私有配置/报告使用的认证 Endpoint IP 还须以精确
`/32` 或 `/128` 从 capture 中排除；这是从同一 View 单向派生的本机路由输入，不授予 Service 权限。
Android 私有配置/报告的 Go socket 与 DNS 查询同样使用活跃 VpnService 的 protect 回调；该回调在 capture
之前安装，在确认关闭后撤销，失败则拒绝连接。具名 Endpoint 只经 View 的规范解析器查询，逐次拨号使用
所得 IP，原 TLS 名称及 SPKI 保持；不把可能变化的域名答案当成永久 TUN 排除。纯渲染不查询 DNS，
字面 Endpoint 仍产生上述精确排除。未配置解析器的具名入口与资源明确失败，不借系统 resolver 或 hosts。
解析器来自 Invite 的初始设备配置或随后普通 device.put；业务权限变化不应无意移除未编辑的 DNS 配置。
裸 IP 继续使用原 UDP/53 与截断后的 TCP/53；DoH 只经指定字面 IP 的 HTTPS POST 查询，校验证书 IP 身份与 DNS 问答对应关系，拒绝重定向、异常状态、类型、长度和截断。
共享 Go 连接最多并发两个解析器、每个同时查询 A/AAAA，沿原总期限与取消清理；加密端点失败只尝试同一认证集合中的加密备用。
数据面将同一集合派生为原 DNS server 值和物理 outbound 的 DNS Lookup 规则；除最后一个之外使用接受 IPv4/IPv6 全地址的响应条件，使查询错误继续到下一解析器。
这些条件仅筛选 DNS 响应，不产生业务路由或 ACL；普通业务仍须匹配其 Service。原 IP 集合的渲染不变。
Linux WG 发送资源的具名拨号坐标保留在完整运行模板中；仅在既有资源 worker 请求该资源时，
由原生准备阶段使用当前 View 的认证解析器解析，受本次总期限、预算与取消约束。纯投影不查询
网络，启动不预先解析全部 WG 资源；未知或准备失败只影响本次有限请求，不制造网站故障。
认证域名、peer 公钥、原精确 principal、测量规格和签名原文不变；临时 IP 只属于本机执行。
未配置认证解析器时具名资源明确失败，不使用系统 resolver、hosts 或旧解析器补值。
普通 relay 边不再投影为宿主管理邻接，因此没有“先解析所有 host peer、创建接口、周期重写
管理路由”的运行链。正式管理入口仍由认证 Endpoint／DNS 和 website underlay 提供；
旧接口执行与事故修复记录仅按历史原义保全，不成为新业务候选的前置条件。
最小验证覆盖无 DNS 的字面地址、认证解析与拒绝 fallback、请求取消和迟到结果、新增资源的
按需准备，以及不改宿主网络的真实 WG 中继业务。解析失败不能关闭无关合法连接或更新旧样本期限。
这项 Android 平台 socket 控制不证明 Linux 初始 namespace 的 auto_route 安全，不能用于绕过宿主门禁。
Linux HostAdapter 只在隔离 capture namespace 内将这些 underlay endpoint 的解析结果以逐主机 `/32` 或
`/128` 投影为 TUN 的本机 `route_exclude_address`，使私有控制、引导、
报告和 tunnel 连接不依赖某条业务 policy；本机运行投影不得自行提供或扩大该字段。DNS 变化时重新
解析、重建本机投影，旧结果不是权威也不能扩成网段。这个排除只防止 endpoint 递归进入 TUN，不是宿主 LAN、
管理面或默认路由的安全边界。

### TUN 域名目标的传递

正常入口是应用先经 TUN 查询服务名称，再连接返回地址。仅把 DNS 反查或 TLS/HTTP 名称写入本地
匹配元数据不足以完成这条链：Hy2 仍会发送原 IP，接收端的域名 ACL 必须拒绝。HostAdapter 因而只对
进入 `tun-in`、命中当前 Service 域名 matcher 的 A/AAAA 查询使用数据面的本机合成地址映射；
包含拒绝规则中的名称，以免较宽 IP 服务绕过域名拒绝。其他 DNS 查询、Mixed 请求、私有 control 和
数据面自身的 underlay 解析仍使用认证解析器，不进入该映射。

映射只恢复请求的 FQDN 与端口，随后完整执行原有歧义拒绝、Service/Policy 和 selector；最终出口
解析该 FQDN。字面 IP 保持 IP，不能因 SNI 或此前同 IP 的 DNS 答案变成域名请求。接收端继续只按
Hy2 实际目标授权，不启用接收端 sniff 或扩大 IP ACL。明确指向映射池内部的真实目标前缀须拒绝执行；
较宽的默认 IP 范围不把本机映射池声明为真实目标。合成地址仅存在于已授权的 capture 边界，
两族答案都须被捕获。没有认证解析器时不补系统 DNS 或公共默认值。

domain、wire、持久和 UI 均沿用现有 Service、签名 View 与报告；保全原签名字节，运行 JSON 继续由当前授权单向派生。
本机 DNS 配置和地址映射是单向运行投影，不是新增权威。映射缓存不得保存授权或决定 selector，
停止、撤权和重启均须重新执行当前 LKG 的规则；缓存不能让已撤权名称恢复。重启须保留仍被应用缓存
的地址对应的原名称，不能重新分配给另一名称。丢失映射的连接拒绝，应用须重新查询；缓存可删除重建，
但删除前须停止该 capture 的 workload 并清除其 DNS 缓存，不能运行中自动清空或以缓存恢复代替授权验收。
新增操作成本限于受保护的本机映射缓存，无新的配置键或管理入口。
Windows 同一交付形态的配置共用受保护的本机映射缓存，切换配置仍重新检查各自授权，不共用身份或 LKG；
Android 的单 VPN 使用应用私有缓存，Linux 缓存与隔离 capture 的运行目录绑定。缓存损坏保持原字节并拒绝启动。
地址与名称必须在 DNS 回答前耐久保存；分配位置落后时跳过已有地址，地址池耗尽时拒绝，不能通过循环复用
改变仍被应用缓存的目标。未修复这些恢复语义的数据面制品不得执行该域名 capture。

最小验证为实际 TUN DNS → Hy2 FQDN → HTTPS、IP 前缀请求保留 IP、任意 IP 携带允许名称的 SNI
仍被接收端拒绝、underlay 查询不返回合成地址，以及正常/异常重启与撤权后旧地址不改变目标或复权。

ICMP 结果只能作为地址 RTT 提示：

- ICMP 成功不能把候选改成 `available`；
- ICMP 失败不能把候选改成 `unavailable`；
- ICMP RTT 不能冒充 HY2、WireGuard 或业务端到端延迟。

同一来源、资源、底层网络代与执行规格的首跳检查去重，当前在途测量合并；同一物理首跳
可以被多个配置消费者复用，但不同凭据的认证成功不能互借。WG 与 Hy2 分别记录真实结果。
有向中继样本绑定 Link、传输规格及来源网络代，正反独立；计数器不制造连通性或业务成功。

WG 准入测量使用同一常驻实例的原生来源通道，只允许认证诊断用户访问精确执行地址的固定
端口，再由接收端校验 AdmissionEcho 的 Policy。它尚无业务连接上下文，不能先进入要求该
上下文的业务出站；普通业务仍必须通过逐连接授权，不因诊断通道取得目标转发权限。

采样机会来自节点统一请求率、并发、字节与超时预算，不从服务数或完整路径数扩张。各请求
独立超时和取消；完成时间决定原始测量时间，排队和重发不续期。取消后等待进行中的请求退出，
不生成网络失败。公平轮转保证必要备选和恢复路径仍被测量，不能仅因已经有可用连接就停止优化。

旧实现将 Linux 配置检查、测量和有效期绑定为十五/三十秒，并等成功样本过期才重测；这些是
需要替换的调度行为，不是业务期限或造成十秒以上交互等待的既定证据。测量周期、样本有效期、
性能换路最小间隔必须独立定义；当前缓存的原时间与截止保留，新的观测不倒改旧已签字节。
配置同步、报告和 UI 不等待测量轮次，慢请求不阻断本地业务。具体间隔由时延、流量和耗电证据
确定，不从旧轮询常量继承；也不把样本过期解释为正在使用的连接发生故障。

底层网络代变化后，上一代观测不再决定当前状态，候选先回到 `unknown`。启动和切网
都不得等待观测齐全；缺失观测保持未知，也不得通过补样本制造健康状态。

#### 周期回读不足与执行失败

已成功启动并完成首轮完整回读的 generation，在后续刷新中遇到明确的局部网络超时，不应把一次观测
不足升级为整代应用失败。先回读全部资源的真实进程/UDP listener 及本 generation 精确 WG 所有权；
只有这些执行边界仍成立、认证 LKG 未变且失败仅为明确超时时，保留执行，投影 runtime `unknown`，
下一次既有刷新重新取得完整证据即可在同 View 恢复 running。首次启动的完整 readiness 不放宽。
TLS/证书/身份/认证或 ACL 不符、所有权丢失、持久化与清理失败及未分类错误仍失败关闭；取消按原停止
和精确清理链执行。`net.ErrClosed` 本身不能证明只是超时，不能掩盖携带该原因的 TLS crypto 错误。

domain、签名 wire 与身份 persistent 不变；原四态 RuntimeReadback 已包含 unknown，本机 schema 3 Status
使用同一含义。unknown 的当前 applied digest 为空、resources 与 WG counters 缺席、当前 selection/观测
展示为空；唯一 LocalState 中原样本及截止保持，不清空有效失败或延长窗口。实际测得的 components
仍可报告，UI 显示其原坐标但完整应用保持未知。日志只记录固定操作/失败类别及子进程退出状态或信号，

存在，也不能按普通超时继续把整个执行当正确。

必要验证为局部周期超时后进程与真实 WG 业务保持、unknown 正常回读及同 View 恢复；启动、crypto/
ACL/所有权/清理失败仍拒绝；停止与撤权不恢复旧权限；unknown 保留实际组件而拒绝旧资源证明，原样本
不续期。无新生命周期、自动重启 service、重试调度器或持久完成状态。

#### 数据面的消息工作集

传输需要当前活跃连接、正在收发与排队的消息，不能由历史流量增长持续保留无界的消息池。Linux WG
批处理大小必须与 bind 的 message 数组、TUN 读取和 GRO/GSO 分段边界一致；缩减只能改变本机工作集，
不能截断合法 UDP 聚合或改变认证、AllowedIP、Service/Policy。消息池保留和队列总字节按当前执行
资源设有限边界；取消与关闭先终止新交付并等待在途处理，再释放同一 owner 的缓冲与接口。

消息归还后，发送与接收协程的临时批数组也必须清除同批的正文引用；仅缩短切片长度不会释放底层
数组中的引用。下一批较小、发送或交付失败、peer 仍运行但已空闲时都满足这个边界，不能让已归还的
正文绕过消息池的保留上限。同步发送和交付完成前仍保留正文，不能为释放内存破坏在途所有权。

原生首跳探测的 TCP DNS 请求使用同一 WG 执行实例。接收端 DNS stream 的读方向结束后，由该连接
的执行者等待已接收请求的响应完成，再完整关闭连接并通知原调用者；不能把 EOF 当作调用已结束而
留下另一端的 socket、复制协程和连接条目。对端仅关闭写方向时仍须送完响应，超时、取消和解析或
写入失败则解除本连接的阻塞并释放资源。该完成通知只属于本次连接，不保存探测历史或新增健康事实。

domain/persistent 仍为原 TransportResource 与设备/Service/Policy 授权，wire/LKG 携带派生中继段；批数组、消息池和连接缓冲都是
可释放的本代运行资源，不产生第二份权威。UI 继续消费真实业务观测，回压或资源不足不能伪造健康。
先在专用 namespace 用同形 demo 资源测空闲、真实 TCP/UDP、突发和连接排空后的 live/allocated heap、
RSS 及吞吐/延迟，再调整有证据的工作集。最小验证包含最大合法包与 GRO/GSO 边界、突发回压、协议
独立承载、收包与关闭并发及同身份重启；限额和较小常数都不能单独作为通过标准。

目标是在配置入口或报告入口暂时不回应时，已获授权的本地执行仍能处理偏好、切网和有限期观测。
Linux 原刷新循环先等待配置，再执行本地选择并等待报告；一个慢管理请求因此拖延下一轮本地处理。
最小变化是本 generation 中配置刷新和报告上传各自只有一个后台在途请求，本地循环不等待它们。
刷新请求合并；上传只有一个待发送的最新快照，替换尚未发送的旧快照，不积压历史或重发旧采样。
快照保留原采样时间与报告生成时间；迟到、失败和取消不能制造可用结果或续期。

当前 LKG 仍是唯一授权。配置刷新先完整认证并原子接受，再比较实际执行依赖：仅名称、报告、
限制开关关闭时，仅探测配置或无关事实变化不得重建数据面；限制开启时，修改网址也会改变派生
访问边界，必须重新应用相应授权。新增设备不得打断其他设备的共享转发。真正的权限收缩
及时撤销相应旧连接，不因性能连续性保留越权流量。资源变化按其实际影响更新；当前实现仍需
逐 View 停启时，将其记为热更新与连接保持的缺口，不能反过来要求继续整体重启。
本地循环也回读实际身份文件，不能因网络请求在途而忽略其他正式入口已接受的撤权。
持久化错误仍失败关闭；单次网络失败保留已接受授权。没有 LKG 的首次取得授权可以等待配置，
已有 LKG 的启动不能先等待网络。停止、应用失败或换代均取消并等待两个在途请求退出。

domain、wire 和 persistent 仍是原 LKG、Preference、Observation 和 DeviceReport；后台请求、至多

真实报告确认，旧快照的迟到确认不能覆盖较新的选择回读，不影响客户端选择或服务可用性。
没有新权威、队列文件、配置键或操作步骤。最小验证覆盖管理连接阻塞时本地仍更新、在途撤权、
最新快照合并、旧确认隔离、持久化失败、停止取消和同身份重启。

## 局域网 Service 范围

具备 `forward` 职责的网关可认证报告自己的本地 IPv4 前缀；报告本身不产生共享权限。
control 签发的 `local_network` Service 值给出稳定映射 ID、网关节点、本地前缀、等长的虚拟前缀和
固定网关约束。access 的 `PolicyIDs` 选择了属于此 Service 的有效 allow Policy 后，签名 DeviceView 才向它
下发虚拟前缀及到**固定网关**的获授权候选。access 不得提交任意 CIDR 或从网关报告自行生成路由。

`local_network:<mapping_id>` 是独立的 Service scope。客户端只对该虚拟前缀建立精确业务捕获与
路由，在到固定网关的一跳或中继路径中自动选择，不把网关误作互联网最终出口。开发宿主上
这些路由、策略规则和 DNS 投影只能在专用 capture namespace 内应用，不进入初始 namespace。
互联网当前 Policy 的选择不改变 LAN 的独立授权；局域网仅在其策略允许、通往固定网关的路径内选路，
不改变互联网服务的选择，也不扩大为互联网出口许可。
网关按同一授权检查，完成目标地址按主机位对应的转换，并在 LAN 主机没有
回程路由时做必要的源地址转换。只有 overlay 端能主动发起连接；LAN 主机可回复，不能凭映射主动
建立到 access 的会话，不修改 LAN 路由器。

现有原生传输已在接收节点终止 TCP/UDP。LAN 的最终网关因此在获授权的 direct 拨号器内完成
等长前缀转换：配置 `prefix_mapping:{virtual_prefix,local_prefix}` 只由该 Service 单向生成，
保留主机位与目的端口。接入和中继仍传递原始虚拟目标，只有固定网关可转换；不能同时设置 detour
或单地址/端口 override。物理连接由网关本机发起，LAN 回包自然回到同一 socket，不需安装宿主 NAT。
两个前缀精确相等且在 10 段时，转换保持目标地址，范围、端口与接收授权检查照常执行。
网关仅在当前物理 LAN 读回精确吻合时允许该最终拨号；本机 access 仍排除这一 underlay 网段，
其他设备或范围不同的相交前缀继续失败关闭。
不允许 LAN 主动连接 overlay。UDP 每个会话只允许原始目标及其对应回复，不能借已建立 socket
发送到范围外地址或从另一 LAN 主机注入数据；TCP 半关闭须保留返回方向。
域名解析结果仍须处于虚拟前缀，转换层拒绝未解析名称、IPv6 和范围外地址。该执行配置是可再生投影，
不改变 schema 3，不产生新的传输协议、密钥或权限；所有授权仍由原 Service/Policy 的接收规则承担。

一个网段若没有适用的共享 HTTPS 目标，主动完整业务可用性是 `unknown`，不能从 WG/hy2 握手或
任一 LAN 主机的结果推断整个网段可用。真实业务访问可生成**该目标**范围的 Observation。
映射撤销、策略撤权或网关身份失效时，客户端移除相应精确路由、DNS 投影和候选；已见撤权 floor
不得被较旧 DeviceView 重新降低。自动分配的虚拟前缀是 control 签名事实，不由客户端重算或猜测。

## Preference 与 Selection

Preference 是身份中唯一持久选择值，规范字段为 `schema:3,policy_id?,lan_policy_ids?`。
`policy_id` 表达当前一条互联网 Policy；`lan_policy_ids` 为非空时才出现的 ServiceID→PolicyID
映射，仅含本机获授 LAN Service 的独立选择。空映射必须省略，未知字段、空 ID 和错种类引用拒绝。
两者都从 Policy.ServiceID 推导 Service，不能把 LAN 选择混入互联网默认出口。
互联网切换保留 LAN 选择；LAN 切换只影响该映射。撤权分别清除失效选择，不自动选更宽策略。
首次接受 LKG 时，每个 LAN Service 仅有一条可选策略才初始化它，互联网也仅在只有一条时初始化；
之后待选保持待选。历史明确的 LAN 意图由显式一次性迁移保留，不用运行缓存或报告恢复意图。
该值在 domain、规范 wire 与 identity 持久层可逆；运行时分别投影为 `access` 和
`local_network:<ServiceID>` selector，UI 保留原选择交互。不存在第二份 preference 文件。

Preference 表达客户端当前选择的一条互联网 Policy，所属 Service 只从 Policy.ServiceID 推导。
设备的 PolicyIDs 是获准选择的集合，可跨多个 Service，不表示每个 Service 同时独立生效。
旧 `services:[{service_id,policy_id?}]` 偏好是待迁移字节，不能继续作为当前目标；新规范字段
与显式一次性前向替换未完成前，不继续相关写入。保全原偏好，不擅自合并规则或按旧列表挑选新策略。

已选 Policy 仍有效时保持选择；新增授权、暂无路径、网址失败或观测过期不自动换 Policy。
撤权、删除或引用失效不得回落到更宽 Policy 或 Direct。尚未选择时明确待选，不能将设备可选
集合直接合并为业务权限。待选、应用失败和数据面已运行分别回读，不能用偏好推断业务成功。

Selection 是实际应用并回读的结果。性能推荐和当前已建立连接的路径分开，换路时刻只有成功
应用后才更新；性能优化保留存量连接，撤权和真实故障依各自范围处理。实现不能因旧 selector
关闭连接方便，就继续沿用所有原因统一断流的行为。

### 首跳样本参与必要尝试

首跳资格来自当前 Policy、节点职责及认证资源。access 必须测量自己的网络到入口；远端链路
成功不能替代本机首跳结果。管理入口竞速与业务首跳探索分别处理；控制角色不决定业务首跳。
冷启动和切网并发探索，在统一预算内尽快使用可用入口，继续公平探索未知或恢复中的入口。
地理位置只可辅助安排顺序，不能覆盖真实测量或制造健康标签；不固定“2+1”探测预算。

### 远端中继样本与有界业务轮转

forward 报告自身发出的有向链路，出口报告自身网址请求。control 保留来源、规格、原时间和
有效期，客户端通过一次私有认证批次领取相关样本，后续领取差量；缓存丢失重领，不按 Service
各发请求。远端网络代属于远端来源，不能与本机网络代混同；过期或规格变化只使相应证据失效。

持续测量与换路冷却分开。采样轮转由节点共享预算和最久未测决定，不能等成功样本过期才重新
了解网络，也不能在每轮重扫全部完整路径。签名报告序列保留，重复上传不能给旧样本续期。
在途测量合并后，各消费者复用实际请求的完成时间及完整耗时；不能各自按等待结束重新计时，
也不能把后来加入的消费者所等待的剩余时长当成该次测量的完整耗时。

### Android 私有请求与持久提交

加入、配置领取和签名报告的网络等待不持有共享操作锁。锁内只读取本次不可变输入、预留报告序列
及提交经过重新校验的结果；每次私有请求的取消柄只拥有该次网络 I/O，不拥有身份、LKG 或完成状态。
取消须传至实际 Go context/socket，不能只在 HTTP 等待结束后丢弃结果。

配置领取返回同一原始签名 envelope，而非来自旧快照的整份设备状态。提交时重新读取唯一受保护
身份，用当前 high_water、LKG 与绑定验收 envelope，保留期间预留的报告序列。若本次输入的 View
已被另一操作替换或 profile 已删除，迟到结果丢弃；不能写回旧状态或重新创建配置。加入尚未取得
首份 LKG 时，结果仅可替换仍逐字节等于请求输入的待加入身份。失败不删除身份或降低认证进度。

domain/wire 仍是既有身份、签名 envelope 与报告；persistent 仍只有原受保护身份记录；runtime
只有可取消调用及短锁快照；UI 分别回读加入、配置接受和运行结果。最小验证覆盖慢领取期间报告
序列预留、配置先后到达、取消、删除及重启，证明原签名字节、身份和进度保全，并以真实慢通道
验证停止/切换及时完成。代码或单测通过不能代替该交互验收。

Android 的本机 selector 同样遵守短锁提交：操作锁内只取得当前身份、Preference、运行配置对象、
网络代与调用所有权；回环 socket、启动等待、CAS 应用与完整回读均在锁外。每份配置沿现有运行
对象串行执行 selector I/O，报告读取和停止不等待该串行锁。运行中的新用户选择、认证配置接受、
网络代或停止会取消旧调用的实际 socket；初次启动尚未应用时更改 Policy，则由同一有效启动重新
读取已保存的 Preference。对象身份和 Preference 的提交校验阻止迟到结果，包括 A→B→A 选择，
覆盖新状态。该调用句柄和互斥只属于临时执行，不增加持久阶段、授权或管理对象。

本机 API 启动只有一个总截止，不按重试次数重复支付 socket 超时；只重试尚未就绪的 I/O，
CAS 冲突及非规范响应直接结束本次请求，不重发旧 PUT。上层仅在同一调用仍拥有当前运行输入时，
最多三次重新读取、计算并 CAS；被替换的调用立即退出。协程取消与截止必须关闭实际 socket，
慢速分段响应不能绕过总截止。每个 scope 的 candidate、targets、Policy 和连接上下文全部
应用并回读匹配后，才确认该 scope 的 Selection 与性能内存。同一调用先处理 access 的初始
GET、准备、CAS 与最终 GET，立即发布其完整确认，再处理独立 LAN；首互联网可用不等 LAN。
这仍是一份可取消调用内的顺序 I/O，不新增并行 scope 调度器。

一次性调用仅记录仍可能写入及已可能写入但未确认的 scope。取消、替换或失败只使这些未
确认写入的回读失效，不丢掉其他 scope 的成功确认。关闭客户端 socket 不证明服务端尚未
提交的旧 PUT 已经停止；接管未确认 scope 时，即使新选择与 GET 内容完全相同，也须沿
现有完整选择 CAS 推进一次执行 revision 并回读，使旧请求失效。本次普通 GET 或冲突重读
不能消除这项未确认状态；只有新的完整 CAS 和回读才能确认。已确认且无旧写入悬疑的重复
检查仍可只读，不因此每次都换 revision；只读调用不制造写入需求。此规则对互联网及 LAN
scope 相同，不改变签名权限、认证进度或旧业务连接。某 scope 资源准备失败时，实际旧选择
仍符合当前 Policy 才可保留；否则须真实应用并回读拒绝，不能构造拒绝结果或把局部准备失败
写成网络失败。手动更换 Policy 立即更新新连接选择，仍获授权的旧连接保持；显式“重建该服务
连接”才关闭对应存量连接，不能从偏好变化推出授权撤回。真正必须拒绝却无法确认时，保留现有
安全停止边界，原子核对当前调用／VPN 会话并提交停止意图，迟到停止不得关闭新实例。

仅 LAN 在途不阻挡 access 首选确认，策略菜单也不以后台调用忙碌为由拒绝用户输入；新选择
沿原取消和 CAS 校验接管。性能内存只合并成功 scope，失败项不能推进应用时刻。局部运行
可供普通请求使用，完整报告仍须覆盖当前必要 scope、Preference 及完整资源应用确认；未齐
保持 unknown 和空 applied 证明，合法权限确认与独立样本可继续共享。同 View 纯投影不能
冒充完成。未确认项沿既有检查和测量完成入口恢复，不新增时钟、持久阶段或重试管理器。

domain、签名 wire 与 persistent 不增加对象或字段；runtime 的在途范围只归本次调用，已
确认的 Selection 则按当前运行绑定保留，绑定失效时清理。UI 只展示实际确认及准备中／未确认
状态，不能倒写授权或样本。
最小反例覆盖阻塞回环请求期间报告与停止能完成、取消释放真实 socket、慢响应总截止、当前调用
CAS 重读与旧调用退出，以及配置／网络／策略替换后的迟到结果不能提交。正常业务及长连接保持
另行沿真机运行验证。

### 同一服务的多个测试目标

各网址保留独立的可达性、耗时、测量位置与有效期。单网址失败、部分样本、缺样本和取消应
分别处理，不由某一网址制造整个互联网的失败结论。没有网址也能建立获准连接。
固定出口时忽略出口网址差异，所有目标共用按分段观测得到的入口和后续链路优选；HTTPS 请求
总耗时不能当 RTT 相加。允许多个出口时保留各目标的差异，不宣称一个平均值能证明全部目标最优。
用户已确认按实际目标分别保留优选，无样本时使用当前 Policy 的默认优选。连接目标匹配规范
域名/IP＋端口，路径或 query 不构成不同连接目标；同一连接目标下的多个 URL 保留各自证据，
只有可比且持续的改善才改变该目标的新连接选择。不先把各网址平均成 Service 总分，也不增加
地域库或强迫未知目标先等待探测。网址没有独立业务数量上限；既有完整值大小与节点预算仍约束
执行，增加网址只增加公平轮转等待，不改变原样本的截止。
同一 host/IP＋端口的多个 URL 无法按加密 HTTPS 路径区分连接；它们保留各自证据。性能优化
要求在可比的新旧样本中至少一个 URL 显著持续改善，且其他有可比样本的 URL 没有显著回退；
证据冲突时保留当前选择并继续采样，不按 URL 顺序或单次最小值裁决。缺样本不补零，也不阻止
先用当前 Policy 的可用默认路径联网。分段 RTT 仍与各 URL 的完整请求耗时分开。

### 多 Service 配置与唯一当前互联网 Policy

可以配置、授权多个 Service 及 Policy；客户端当前互联网只选择一条 Policy，Service 随之确定。
因此不需要地域归属规则来解决“多个普通互联网 Service 同时生效”的问题。配置共存、授权可选、
当前选择、运行回读和存量连接不得混淆。LAN 仍按独立授权边界执行。

## 跨层同构

下表完整规定八个概念在 domain、wire、persistent、runtime 和 UI 中的对应关系。
“派生”表示该层不得另存一份可写副本；“无”表示该概念不需要出现在该层。

| 概念 | Domain（语义） | Wire（跨进程） | Persistent（重启后） | Runtime（当前进程） | UI（用户可见） |
|---|---|---|---|---|---|
| `DeviceIdentity` | 设备标识、已认证成员链、签名能力与不可回退已见事实 floor | 只发送标识、公钥及签名证明；不发送私钥 | 私钥进入平台安全存储；信任绑定、前沿、floor 与新 LKG 同一原子提交 | 提供验签边界与签名能力，不参与排序 | 加入状态与公开标识摘要；永不显示秘密 |
| `CertifiedLKG` | 最近一次验证成功的签名设备视图 | 完整规范 View、签发 control 签名、连续成员证明、签发者事实前沿与设备绑定 | 完整 envelope 原子保存，与信任绑定及 floor 同步替换 | 解析为只读输入；不能证明全网没有未见撤权 | 显示来源、已见前沿和是否陈旧，不宣称网络可用 |
| `RouteCandidate` | 当前 Policy 的入口、首跳资源及最终出口，Service 随 Policy 确定 | 不交付签名候选；同一 View＋Preference 本机派生 | 不持久化 | 只生成当前互联网与独立 LAN 选择；链是可行性估计 | 显示入口／最终出口，估计中继须区别实际连接 |
| `RuntimeCandidate` | 路径的可执行投影及稳定身份 | 不单独传输；所需入口和资源材料来自私有认证配置 | 不持久化独立副本 | 按调用方平台能力投影，供 adapter 按资源 ID 复用 transport / outbound | 通常只显示协议和入口类别，不暴露秘密参数 |
| `Observation` | 按 resource/link/egress/service 分层的真实来源、规格、目标及原时间 | 私有认证报告保留来源、目标、范围和 `link_spec_digest` | 不作为配置权威；可留诊断历史，但恢复时不得直接当作当前结果 | 当前网络代的有限集合，摘要不匹配即失效 | 显示 available / unavailable / unknown、实测范围与陈旧状态 |
| `Preference` | 当前一条互联网 Policy 与各独立 LAN 的选择或待选意图 | 报告只读采样本机意图，不是设置同步；旧 policy_choices 仅按原义保全，不能决定新偏好结构 | 只保存一份本机用户设置；报告历史不成为设置权威 | 作为纯选择函数输入；停止或执行失败仍可上报保存的设置 | 客户端唯一可编辑的选路意图；Web 分别展示已报告设置、原时间和实际选择 |
| `Selection` | 完整原生回读确认的 Policy、默认与按目标选择及自身修订 | 可通过私有认证状态报告上送 | 不作为下次启动的权威；事件可供诊断 | 当前实际候选及回读时间 | 与 Preference 分栏显示，明确“当前实际路径” |
| `HostAdapter` | 平台能力边界 | 无独立 wire 对象 | 只使用平台既有安全存储与服务配置 | 在平台隔离边界内执行 load、apply、readback 和真实 outcome 采集 | 提供能力/错误，不提供第二套选路开关 |

同构必须满足以下检查：

1. 同一候选在 wire 派生、持久恢复、运行时和 UI 中使用同一个稳定身份。
2. UI 上的授权、可用性、用户偏好和实际选择分别来自 LKG、Observation、Preference
   和 Selection，不能用一个字段代替另一个。
3. wire 或持久层没有 `RouteCandidate` / `RuntimeCandidate` 的第二份可编辑清单；
   重启后从同一 LKG＋Preference 得到相同候选，实际选择仍须回读。
4. 平台脱敏可以删去私钥和 transport 秘密，但不能改变路径、最终出口、状态或版本语义。
5. Android、Linux 与 Windows 对相同 LKG 与 Preference 得到逐项相同的 `RouteCandidate` 身份；再给相同平台能力值
   和观测输入时得到相同可执行集合与选择结果。能力值不同只裁剪不可执行集合，不改变授权候选 ID，
   也不让 `HostAdapter` 发明另一套选路规则。

## 持久与派生边界

必须持久化的网络权威与用户偏好只有：

- `DeviceIdentity` 的安全材料和不可回退 floor；
- `CertifiedLKG` 的原始认证字节；
- 用户明确设置的 `Preference`。

`RuntimeProfile` 和底层 JSON 从稳定 LKG＋Preference 单向派生，不进入签名 View 或持久身份。
宿主临时配置只供当前实例消费，停止删除；重启从唯一身份重建，不能将临时文件恢复为授权。

身份 store 在读取实际规范字节和接受新值时完整认证，并私有持有已验证的领域值。取 Invite 或
LKG 只需要复制该值以隔离调用者；不把同一私有值重新编码、解码与验签。复制须保留具体 payload
类型、nil 与空集合，以及嵌套指针、接口、数组、切片和字典的值，调用者修改任何副本不得改变
store 或原字节。范围限于现行规范领域值；不支持的内存种类或未定义私有字段失败关闭。
正式编码、外部输入解码和写入的认证门禁不变，不新增缓存、持久字段或权限。

在原文件锁内读取当前实际身份字节，核对权限、保护格式和完整读取。仅当完整字节的 SHA-256 与
本句柄已经认证并私有持有的状态一致时，可复用该值；不凭 mtime、大小、签名 ID 或报告序列跳过
认证。这个内存摘要是可删除重建的派生值，只在完整认证载入或新规范字节提交并精确回读后更新，
不持久化，不产生新的完成判定；重启首次读取、摘要缺失或任何字节不同均重新完整认证。
Reload 中领域值完全相同便没有前进需要再次认证。任何不同值仍检查身份、LKG、floor、序列与
偏好的原前向规则，再更新私有值。LKG 是否变化直接
比较规范领域值，依据唯一契约的往返等式，无需为比较再运行一轮签名 wire 编解码。
domain、wire 与 persistent 保持；runtime/UI 消费独立副本。最小验证覆盖嵌套副本隔离、
输入值接受后的隔离、原字节重启、独立 writer 前进、回退及损坏/非规范原件拒绝。

报告预留序列只修改同一 DeviceIdentity 的 ReportSequence。正式入口仍在文件锁内读取并完整
认证当前规范身份，再从该值预留下一序列；并发 GUI/daemon 不能用旧句柄覆盖新 LKG、floor 或偏好，
溢出或尚无 LKG 拒绝。新规范字节编码时再次验证领域值，写临时文件并同步，回读明文须与这份
已验证的规范字节完全相同；原子替换并同步目录后再次逐字节回读。相等即继承该字节串已证明的
规范与认证属性，无需为同一次写入重复解码、投影和验签。Windows 仍通过原保护适配器解密回读。
任一步失败仍锁定本句柄，未持久完成的序列不能发出报告；重启和独立句柄首次读取仍完整认证。
不增加缓存、状态文件、协议字段或操作步骤；domain、wire、persistent 不变，runtime 与 UI 仍
消费同一身份。最小验证覆盖并发序列、同期新 LKG 与偏好、写后重启、损坏与非规范原件拒绝、
保护适配器与写入失败，以及真实报告入口持久确认和页面回读。

平台可以持久保存当前网络代的有限 `Observation` 诊断缓存；它不是认证网络权威，过期、换网或验证失败后
必须回到 unknown，缓存可删除重建。Android/Windows 的本机 profile 目录保存用户命名、稳定本机 ID 与
恢复意图，必须按各自模型规范持久往返并在失败时保留；它们不是网络授权或实际连接的权威，但不能当缓存删除。
当前运行事实仍从当前输入或宿主回读获得：

- `RouteCandidate` 与 `RuntimeCandidate` 每次启动重新派生；
- 当前 `Observation` 由实际网络结果产生，历史记录不能在新网络代恢复成健康事实；
- `Selection` 每次由 selector 回读恢复，而不是相信上次写入的期望值；
- `HostAdapter` 是代码边界，不拥有另一套业务状态。

不增加候选数据库、健康缓存权威、切换 journal、阶段表或
影子 selector。诊断事件可以记录，但事件不能反向成为当前状态。

## 状态转换与恢复

### 首次加入

1. 平台本机生成 `DeviceIdentity`，从可信交付的 Invite 固定网络锚、签发者和当前可验证的
   `ControlConfig` 成员链；首次 claim 只找签发者。扫码 Invite 只能授予 `access`。
2. 验证收到的完整 DeviceView、签发 control 的成员资格与签名、连续多数签名的成员变更证明、
   签发者事实前沿及设备绑定。除经连续多数证书明确封存的验证键按封存序列验收外，已见撤权不得在新 View 中消失；通过后与信任绑定、已见高水位
   原子保存为 `CertifiedLKG`。事实及其因果依赖由签发 control 验证；设备没有全网事实，不能独立重算
   该闭包。签名 View 不能证明没有尚未传播的撤权。
3. 纯核心逐项解析该设备 PolicyIDs，从有效 allow Policy、其固定 Service、首跳资源、节点链和有序 `LinkID` 派生授权候选，再按平台
   实际能力投影可执行候选；`HostAdapter` 按资源 ID 复用并安装必要运行配置。首份 View 没有
   派生中继段时仍可经设备认证私有入口领配置，并按授权使用共享首跳。
4. 先持久化按当前 Policy 及撤权校验后的 `Preference`；已有 PolicyID 时在该策略内选择一个未被证明不可用的候选，应用并回读；当前互联网策略待选时保持拒绝；
   没有时业务保持 `unknown`，仍可经现行私有入口领取修复 View 和报告。
5. 并行采集必要的真实 transport outcome；结果到达后再以同一纯函数重算。

第 4 步不等待第 5 步，所以首次启动不会被测量阻塞。
Android 在签名、成员链、设备绑定、floor 和受保护原子写入回读通过后保存该 profile 的
`CertifiedLKG`；`active_profile_id` 只在 libbox 配置校验、VPN 启动及 selector 实际运行回读后产生。
当前互联网 Policy 非空时，首次 `CONNECTED` 还须确认该 Policy 的非拒绝默认选择及其完整
连接上下文实际读回一致；权限应用成功、资源准备完成或回读到 `reject` 都不能代替首条选择。
没有当前互联网 Policy 时，完整的待选拒绝可以成立，独立 LAN 不因此获得新的启动门禁。
`STARTING` 期间测量、配置跟随和报告继续；首条合法选择一经确认即发布，不等全部候选或
网址测完，也不重启已在执行的报告／测量循环。资源回读、网络变化和选路通知均只唤醒重查，
发布前仍须核对当前 VPN session、配置对象、认证状态、Preference 及完整原生回读。
此后测量或优选更新不将已连接状态退回首次启动，不关闭合法存量连接。运行连接状态仍不
代表普通业务已经成功，实际请求的 DNS、TLS 与正文结果分别记录。
运行应用失败时不把该 profile 画成 active，旧运行路径只有仍获新 View 授权才可继续。
后续 DNS/HTTPS 结果只决定相应 Service 的业务观测，
目标缺席为 `unknown`，真实失败为 `unavailable` 并按同一选择函数尝试必要 fallback；
不能因目标缺席或探测失败删除已认证的 LKG，也不能把 active 画成业务健康。

### 进程重启与离线

1. 从安全存储加载身份与信任绑定，重新验证持久化的 LKG。
2. 确定性地重建候选。
3. 先读取宿主 selector；仍被授权且未被当前结果证明不可用时保持它。
4. 没有可保持的实际选择时立即选择一个合法候选，不等待控制面或观测。

控制面不可达时继续使用认证 LKG。认证失败、未经封存证书授权的事实前沿回退或没有任何合法业务候选必须明确报错，
不能退回旧网络路径；业务候选缺失不阻止已认证设备经现行私有入口领取修复 View 和报告 `unknown`。

### 新认证配置

新 LKG 只有在签名、设备绑定、成员链证明、签发者事实前沿和 floor 全部通过后才能替换旧值。
成员变化时，envelope 必须从设备已固定的成员表起提供连续的后继表，每步引用前一表摘要，
由旧表计算出的多数在同一轮次签署同一提案，并携带失去资格的验证键的封存序列。客户端逐步核对
网络锚、成员 ID 与验证键、签名集合、封存序列及最终签发者资格；不接受仅由新表自签的跳跃。
没有成员变化时证明序列为空，但仍必须验证签发 control 当前有效。
新 View 的事实前沿对未封存键及同键未触发例外的历史单调，不能遗漏仍有效的撤权或冲突事实。只有连续
多数成员证书明确封存某验证键时，才可把**该键**的验收前沿降至证书封存序列；原已认证高水位、
不可回退 latch 继续保存；旧 LKG 在新值验收失败时保留，验收成功后仍只保存一份当前 LKG。其他键、成员链及现网全局认证 floor 不回退。
留任 control 把自身证书验收前已持久接受、可取得原始证据且超过封存点的撤权自动重签为
引用原事实的有效后继事实，并在放宽本机运行授权或交付新 View 前核验其效果；原始证据全失时无法重签，设备仍可凭证书接受新 View，可能恢复未知的旧权限。
设备在替换前对比旧 LKG 与新 View 的可见授权差异，必要时记录非权威诊断事件；高水位超过封存点时 UI 标记可能复权，但不能由 View 或 floor 反推全部遗漏撤权。
留任成员序列跨换届连续；同一有效事实集合的投影不因本机曾见事实而异。
只有完整 View、成员证明与对应验收前沿均通过，才原子保存信任绑定、前沿、LKG 与原已见高水位。
漏项、乱序、旧格式事实、任意新根、验签或落盘失败均保留旧 LKG 与原高水位。
替换后重新派生候选：

- 被撤销的候选立即停止承接新连接；
- 仍存在且身份相同的候选仅在当前网络代、观测范围及其相关认证执行/探测输入均未变化时复用观测；
  其中每条引用链路的 `link_spec_digest` 必须相同。相同 `LinkID` 或资源 ID 的规范内容变更，只使该链路
  及包含它的候选观测回到 `unknown`，其他输入未变的候选不受影响；入口、RuntimeProfile、DNS、Service
  matcher 或 HTTPS 探测目标变化也须使依赖它们的旧观测失效；重启后无法证明相关输入仍相同的缓存保守置
  `unknown`；
- 新候选为 `unknown`，可以在没有可用候选时被立即尝试；
- 即使候选 ID 未变，只要资源规范内容已变，就须应用新资源并回读 selector 与实际链路，之后才更新
  `Selection`；旧配置的 readback 不能确认新 LKG 已运行。

Linux daemon 在运行期间沿现有配置请求取得更新，不向每台设备广播全网事实集。control 对相同完整
认证输入复用配置响应，证明和前沿变化即使执行 View 不变也产生新响应；已认证 LKG 的
短确认按[配置领取的传输摘要](../core/enrollment-endpoint-model.md#observation)执行。
新 View 的签名、规范形状、设备绑定、成员证明与前沿校验通过后，先原子提交唯一新
LKG、信任绑定及 floor，再按新授权收口运行投影。宿主 preflight、组件验证、进程启动和运行回读
属于后续应用，失败不能撤销已经接受的认证状态或恢复旧授权。
同一监督器按实际变化更新相应资源、权限和路由；无需替换实例时保持存量连接，确需替换时才
建立相应新运行代。listener、selector、链路资源及配置摘要回读成立后才报告新 View 已应用，
不能把旧实现只能整代停启当成新设备加入必须打断其他设备的理由。
新代失败时只回收本 generation 的执行对象。旧配置或资源只能在逐项证明其候选、凭据、ACL、入口及
其他执行输入仍符合新 LKG 时继续或恢复；不能证明时停止相关业务流量，保留设备认证的配置、报告及
修复入口，显示“认证配置已更新，运行未应用”。下一次尝试继续消费同一新 LKG，重启也不恢复旧权限。
例如新 View 撤销服务 A、同时更新资源 B，B 启动失败不得使 A 的旧路径重新接纳连接。
这个“运行代”只是进程内调用边界，不持久化、不形成阶段表或第二份 authority。

#### 新报告的观测投影

Android 的互联网与 LAN Scope 各自完成 GET、准备、CAS、回读和确认。当前权限已完整回读，
但仍有 Scope 待应用时，正常报告保留相同 View、网络代、运行实例及当前偏好下已确认的选择，
未确认、被接管或尚需 CAS 的 Scope 不填；两个保存意图继续独立报告。runtime 为 unknown、
applied 留空，permission_view_digest 必须匹配当前 View。全部 Scope 确认后才能报告整实例
running 与 applied；停止、失败或权限未确认时不报告选择。桥接器校验资格和 Policy，不能从
Preference 或权限证明制造选择；业务样本仍要求完整 running，不随部分选择放宽。

执行选路的 access 和 forward 都可领取当前 Policy/最终出口约束内所需的远端样本：access
仍须自己测首跳，forward 仍须自己测后续有向链路，二者不能被远端结果替代。转发权限来自原请求
的授权上下文，不要求 forward 获得来源设备的 access PolicyIDs。无相关消费者的节点不领取全网
观测；control 继续验证、汇总和批量交付，不包办所有业务选路。旧的“仅 access 领取”属于待改实现。

Linux、Android 和 Windows 在现有采样缓存及当前授权范围内汇总真实样本，按现有规范排序；先检查完整
Observation 集合，再投影 `observed_at <= reported_at < valid_until` 的项。发送端可用有界、可删除的
内存摘要集合省略已获完整报告 ACK 确认的相同样本；缓存绑定来源公钥与原样本，不改变采样时间和
有效期。失败、取消和错序 ACK 不确认；缓存丢失或并发请求最多造成重复上报。共用时间投影纯函数只消费
显式报告毫秒时间，不读时钟、不修改输入或本地缓存，未选候选、有效失败与 unknown 均保留。
在签名前完成投影；序列持久预留、冻结和发送沿各平台原入口，失败允许消耗已预留序列，重试不重筛、不改时间或原件。正常链为采样/保存缓存、
组装时投影、签名上传、control 持久化、页面从原件索引回读；后续报告未携带某项不删除其有效原样本。
失败不删除缓存，不新增持久 outbox 或逐样本 ACK 协议。原件定位和差量领取见
[共享测量的原件定位](../core/current-contract.md#共享测量的原件定位与跨报告保留)。
报告组装前已过期且未首报的样本不再补入远端诊断；本地过期失败仍可用于恢复排序。合法历史原件的
解码验签不增加当前时间限制。Android 报告专用 Kotlin→Go 时间为 UTC 固定三位毫秒，wire 仍为 Unix 毫秒。
反例为同秒 `.800` 样本与报告时间截断成 `.000`：不能将真实先发生样本误判未来，故桥接须保留毫秒。
最小验证覆盖时间两端、未来 1ms、未选候选、过期非法项、缓存不变、延迟重试原文不变及精度往返。

#### 私有通道中断时的显式配置交付

管理 UDP 路径失效后，修正资源端点所需的新 View 不能依靠该失效路径送达设备。已有正常
同步验证签名并写入唯一 LKG，现有 control 也能导出同一签名 View；缺口只是 Linux CLI
没有消费该文件的正常同步入口。最小变化是 `loom client sync -view <file>`，由操作者经
既有受保护管理通道交付 `control export-device-view` 的原件，显式指定后执行普通的当前
View 解码、验签、设备/平台绑定和认证前沿检查，再原子保存同一 LKG。省略该选项仍只走
设备认证通道；不会自动寻找文件或读取历史配置，也不调用历史迁移 reader。

领域、签名 wire、persistent、runtime 和 UI 对应关系不变：文件只是现有 DeviceViewEnvelope
的临时交付物，不拥有身份、版本或完成状态。文件须为有界、owner-only 的普通文件，保留
规范原字节；未知字段、非规范编码、错误签名、其他设备或平台、旧前沿均拒绝且不改状态。
同一有效 View 可以重试，报告序列、偏好、身份和不可回退进度保留。已保存后重启失败仍
保留新授权，不能回退旧文件；正式运行和报告必须另行回读。新增操作成本仅为失效路径修复
期间显式导出、私有交付、同步和重启，无第二配置库或常驻传输。反例是将另一节点的有效
签名文件送到本节点：管理员交付本身不能覆盖设备绑定。最小验证覆盖正常前进与重启、
上述拒绝及失败不写状态，生产修复还须通过正常私有同步和报告证明通道恢复。

#### Linux 更新时保留未变的执行输入

目标是普通设备改权后及时收口它的权限，同时让其他设备仍有效的路径结果继续参与选择。此前 Linux
实现按整个 View 摘要清空观测，并在每次运行代退出时删除全部 WG 接口；即使本机 access 路径和 WG
资源未变，也会重新探测并重建握手。修正只细化这两个派生边界，不增加操作者配置、持久权威或选路算法。
旧实现仍因撤销用户而重启共享 Hy2 listener，这是精确更新与撤权能力的缺口，不能升级为
必须保留的规则。安全撤权及时生效；增员、性能测量和无关配置变化不得因此打断其他合法连接。

观测复用的输入是同一进程持有的前一份已认证 LKG、新接受的唯一 LKG、当前底层网络代及原观测缓存。
缓存原绑定必须等于前一 View 摘要；网络锚、设备身份、公钥、平台和网络代必须一致。逐候选比较
稳定 ID、Service scope、完整候选规范摘要、认证 DNS 以及样本的实际目标与动作；该目标必须仍属于
当前 Service 的探测网址。一个 Service 可以有多个网址，同一网址也可以被多个 Service 复用，
不能要求目标全局唯一。只有相关输入完全相同，才能保留对应业务动作观测；候选删除、动作来源
不能证明或相关输入变化时丢弃该条。节点分段样本继续按其自身完整规格复用，遍历与保存稳定排序。
原结果、测量时间和截止时间逐字保留；复用不制造新的成功、不延长有效期，也不清空有效失败来强制重试。
在原缓存文件锁内完成筛选及 View 绑定更新，并保留同期 CLI 写入的 Preference。重启或缺少前一份
已认证输入时，摘要不同的缓存仍保守失效，不能根据候选 ID 猜测旧权限。

WG 复用当前原生实例中实际持有的 Device、Bind 和用户态栈。完整新权限先提交并确认，再准备
当前有限资源集合；资源描述与认证摘要、来源 principal、peer 及执行绑定须一致。新增或撤下
业务资源不改变初始化地址，也不创建宿主接口或路由；仍合法的旧连接租用它建立时的实际对象和
来源绑定，真正撤权则按当前 source／receiver 权限关闭精确受影响连接。资源准备失败保留新权限
和合法旧流，报告 unknown 并在同 View 重试，不能以重建整代或恢复旧授权掩盖部分完成。
历史宿主对象的清理继续只消费原 generation 的精确所有权记录，不能凭旧 LKG、公钥或相同名称
接管另一进程的接口。正常停止及异常退出只清理本进程拥有的对象，确认清理成功后才报告 stopped。

共享 WG 的数据面关闭必须与收包交付互斥。现有 WireGuard 在停止 UDP peer 之前先关闭设备，
此时接收线程仍可能向系统栈或用户态栈交包；仅检查 dispatcher 非空不能保证随后交付时仍有效。
两种现有设备在开始交付时持有本设备的接收读锁；关闭取得写锁，拒绝新交付并等待已开始的
交付结束，然后释放锁并关闭、等待系统栈，最后关闭它拥有的接口。关闭不能持锁调用系统栈的
拆除操作，避免拆除回调形成锁依赖；dispatcher 的附加、拆除和读取另以短锁同步。
关闭后的包丢弃，不进入宿主或恢复旧授权；重复关闭消费同一关闭结果。此互斥只在进程内存在，
不新增领域、wire、持久字段、配置键或 UI 状态，重启仍从原身份与唯一 LKG 建立新执行。
必要验证覆盖阻塞中的真实交付与关闭、关闭后收包、拆除并发读取，以及有接收流量时的原生停止
和同身份重启；需回读实际业务、单一共享 WG、精确清理及正式 underlay 管理连接。

同一 WG 资源可参与多条 Link，每个对端仍以公钥及精确 AllowedIPs 认证。原精确发送 principal
与 pool／execution 映射按一致快照读取，不能由 Link 数量创建更多 Device、栈地址或宿主接口。
本机接收端口来自受保护输入，纯发送节点使用原共享临时端口；两种情形均不限制合法对端的地址族。
来源冲突、重叠映射、过时 CAS、迟到对象和旧实例提交均拒绝；释放旧租用不能删除较新的同 tag 对象。

先前按宿主接口分组、改名和创建管理返回路由的执行属于历史实现；其原所有权与事故证据保留
原义，仅供严格清理和显式隔离的底层能力验证，不能再从业务图启动。最小验证使用真实用户态
TCP／UDP 覆盖新增资源、来源快照更新、合法旧流保持、撤权精确关闭、空池再进入和同身份重启。
这些组件结果仍须沿正式配置与业务入口回读，不能替代真机、生产或宿主管理不变量验收。

domain、wire 和身份持久层仍使用唯一 CertifiedLKG 与 Observation，不增加另一份权威或 schema。
唯一当前 LKG 仍先耐久接受，原 `runtime.json` 只保留可删除的观测；唯一 Preference 保存在身份文件中；前一 LKG 和 WG
实际对象引用只在进程内用于比较、租用及精确清理，不可成为运行 fallback。runtime 必须应用新 ACL 并重新回读 selector，
UI 和报告只投影该回读及保留原时间的观测，不把句柄复用当成业务成功。

最小验证覆盖：无关改权保留原观测时间；同 ID 的规范内容、凭据、DNS 或目标变化使相关观测失效；
缺少旧输入及重启拒绝猜测复用；同期 Preference 不丢失；WG 实例与合法连接租用保留、撤权精确收口、
旧对象迟到释放不能误删新对象，历史接口清理拒绝未知替代物。最后沿正式改权入口验证未改权设备的既有路径、改权设备的实际拒绝及恢复、正常/异常停止和重启
后的资源与管理连接回读。单元测试或原接口仍存在均不能抵扣这些运行结果。

### 撤权边界

控制面撤销设备时，签名撤权事实使 `Projection` 不再给该设备授权；已知撤权的 control 此后对新的
私有 device tunnel、配置读取和报告
必须在握手处拒绝，Web 也不再投影其授权候选。撤权不会改写已经交付到离线设备的历史 LKG 字节：设备在
尚未取得更新认证状态时仍可按该 LKG 的既有数据面能力继续运行，这一能力边界必须由被引用 transport 的
密钥或服务端授权寿命进一步限制，不能谎报为“客户端已经获知撤权”。分区期间尚未收到撤权的
control 与客户端可能暂时继续按旧 View 运作；这个窗口不能被单签视图伪称为全网即时撤权。
一旦客户端取得不含旧候选的新 LKG，
旧候选立即停止承接新连接；不得以 v1 fallback 或缓存 DeviceView 重新扩权。

### 切网、故障与恢复

- 切换底层网络代：旧观测不参与决策，启动不等待新探测。
- 当前候选真实失败：记为 `unavailable`，从同一 Preference 范围选择可用或未知候选。
- 一跳直达失败：若指定同一最终出口，中继候选仍正常参与选择。
- 后续真实成功：候选恢复为 `available`，不修改授权或拓扑。
- 所有候选均已知不可用：明确显示不可用，不无限轮询、不填充假样本。

操作者确认运营商可能间歇阻断特定 UDP 端口；这属于外部网络环境，失败观测不撤销资源或设备授权。
现行端口恢复入口是对同一 `TransportResource` 签发普通 `resource.put`，只更换已给定映射内的拨号
坐标，保留资源 ID、承载节点、listener 身份与固定密钥。共享 WG 实例继续复用，不能按 Link
单独换端口或启动第二个同密钥实例。对端 endpoint 消费签名资源的 `dial_port`，接收端消费受保护
本机输入的 `listen_port`；二者按操作者已提供的映射对应，不要求数值相同。公开拨号坐标变化
不隐式改动本机 socket；本机输入变化沿现有授权 CAS、热重绑定与回读生效，保留 WG Device
及其他连接。具体执行输入见[配置模型](../operations/configuration-model.md#yaml-字段与基础设施映射)。
原观测按资源规范摘要失效，新端口成功仍须真实 WG TCP/DNS 回读，
不能由资源写入、接口或握手计数制造健康。恢复旧坐标也只能签发新前向事实，不恢复旧 LKG 或降低进度。
持续失败触发的自动恢复由[控制侧端口恢复](../core/control-model.md#wg-持续失败后的端口恢复)执行，
复用原签名资源、配置刷新和真实链路报告；它不属于客户端候选选择函数的隐式副作用。
端口只暂避一周，届满重新参与候选并重新实测；客户端不保存永久端口黑名单。

## 纯核心与平台边界

Android、Linux 与 Windows 必须复用同一个无 I/O 纯核心。纯核心只做：

1. 验证后输入的规范化；
2. 候选确定性派生和身份计算；
3. 观测有效性与三态归约；
4. Preference 裁剪、排序和下一候选计算。

时钟、当前网络代、平台支持的资源传输能力和 selector 回读都由调用方作为值传入。纯核心不访问文件、
网络、VPN 服务、系统代理或全局单例。

Android、Linux 与 Windows 各自只实现 `HostAdapter`：安全存储、配置安装、真实 transport / business
结果采集、selector apply 和 readback。适配器不得自行排名、增加 fallback 分支或重解释
`public_data_ingress`。

### Android capture 边界

Android HostAdapter 默认使用 gVisor 接入 TUN 的 TCP／UDP 流量，运行配置固定投影
`stack=gvisor`。该实现不依赖 system 栈的本机 TCP listener；构建能力缺失或启动失败沿原
错误和停止语义处理，不自动切回 system，也不新增栈选择设置、Policy 字段或持久值。
它只承担本机 IP 流量到既有执行入口的适配，WG 与 Hy2 继续独立传输，并校验同一原始目标、
来源、Policy 及最终出口。UDP 接口适配须保留原域名/IP＋端口和载荷，不能在转换中丢掉域名。
领域授权、签名 wire、身份与认证进度不因栈选择而改变；UI 继续回读运行和实际业务结果。
栈实现升级通过正常停止／重启启用，不能保证已有 TCP 跨栈迁移；运行后的性能换路仍只影响
新连接，已有连接保持。最小回归包括冷启动、双地址族捕获的真实请求、域名 UDP 回包、
旁连接关闭时的已有 TCP、停止清理与重启恢复；有限短测不证明罕见故障率、吞吐或续航。

Android 的 VPN 路由只投影已经确定的正向 capture 范围。原生 `TunOptions` 的 route range 已从
允许捕获的地址中扣除排除项；各 Android 版本统一把该结果交给 `VpnService.Builder.addRoute`，
不在较新系统上重新展开为另一组包含／排除规则。重复提交 loopback 排除项会被平台拒绝，
不能以忽略异常、删掉安全排除或扩大捕获来修复。一个地址族的结果为空时保持不捕获该族，
不因 TUN 具有该族的本机地址就补成默认路由。

普通互联网入口的正向地址段与最终出站的公开地址判定共享同一定义，不从几个探测网址推导。
该投影在没有 LAN Service 时也必须执行；接收资源的互联网权限不能变成本机 access 的捕获许可。
独立 LAN 只加入已授权且没有本机 underlay 冲突的前缀，另加入本 TUN 的精确子网及已启用的
域名恢复 DNS 池；这些内部地址不授予新的业务目的地权限。控制和传输 endpoint 的当前排除
继续生效。该纯投影由各 HostAdapter 复用，不能用默认捕获加少量管理地址排除代替。

领域授权、签名 wire、LKG、身份和密钥均不变化；route range 与 Builder 路由只是单向运行投影。
UI 在 TUN 及 selector 实际应用回读后才产生 active，普通业务成功另行验证。最小验收覆盖被排除
的回环、LAN 与控制／传输 underlay，未列入探测网址的普通业务，以及空地址族不扩大捕获；
VPN 同意、启动失败、重试与覆盖安装均保留原身份、认证进度和报告序列。

### Linux capture 边界与宿主不变量

`RuntimeCandidate` 只回答“已经进入 Loom runtime 的业务流量走哪个候选”，它不授权 HostAdapter 捕获宿主的
任意流量。capture 边界是平台执行前提，不是第九个领域权威，也不进入 DeviceView、LKG、Preference 或报告：

TUN 不被删除为产品能力，但它只能作为 overlay 存在于明确的 capture 边界；物理接口或既有 WireGuard 始终承担
underlay，获准的 hy2/TLS 资源也须沿受保护 underlay 拨号。物理接口显示 `UP`、能收到入站包或 main 表存在默认路由
都不证明安全，必须验证连接的实际返回路径。

同一台机器承担 `control`、`forward` 和 `internet_egress` 是合法的 N=1 部署，不要求 TUN：
数据面入站接收获授权连接，用户态 outbound 直接使用宿主 underlay 出网；“最终出口”仍只是候选路径位置。只有本机 workload 也需要作为
`access` 客户端时才需要 capture。此时平台运行时必须把转发与出网运行时留在宿主受限监听边界，把 access workload 与
TUN 放进专用 namespace；二者仍消费同一 DeviceView，不新增节点类型、候选权威或第二份状态。

- 开发宿主的初始 network namespace 禁止 access/hybrid `auto_route` TUN。未完成隔离时 runtime 与 installer
  都失败关闭；纯转发/出网运行时没有 TUN，不受这一条件影响。
- 默认开发入口是显式 Mixed/SOCKS/HTTP proxy。需要 TUN 时，获授权 workload、sing-box、TUN、table、policy
  rules 和 DNS 全部进入同一个专用 network namespace；宿主只保留一条有明确所有权的窄 underlay 边界。
- 宿主 SSH、LAN、默认网关、现有 WireGuard、DNS、HTTP proxy、控制/Enrollment/报告/tunnel endpoint 和 Loom
  自身 underlay 始终保持原路径。业务 report、selector readback、endpoint 排除或单次探测成功不能替代这些回读。
- 匿名 namespace 与进程句柄绑定一个运行 generation，不创建宿主 veth 或 firewall。正常停止、child/parent
  崩溃、SIGKILL、启动中途失败和重启恢复均终止所拥有的应用树并关闭引用；不得按共享 table 或 rule 范围 flush。
- cleanup 及宿主不变量回读成功前 service 不得宣称 running，也不得自动重启。未知对象或所有权冲突使启动失败。

专用终端若产品需求明确为整机 VPN，可以在该专用设备的初始 namespace 使用 TUN，但这不是开发/控制/混合节点
的默认交付：它必须显式启用，并在 capture 前建立和回读管理网、SSH、LAN、WireGuard、DNS、默认网关与 tunnel
endpoint bypass；没有独立管理通道和失败回滚时同样禁止激活。当前模型尚无这项显式交付输入，因此现有门禁仍
拒绝全部 initial-namespace access TUN，不能用“未来可能支持整机 VPN”绕过。

删除 capture 边界会重新允许应用接管宿主网络控制平面，直接破坏管理可达性，因此它不能被吸收到 endpoint
排除、selector、Observation 或安装 readiness 中。事故背景见
[宿主网络接管事故记录](../incidents/2026-09-21-host-network-takeover.md)。

Linux 的具体映射不增加领域概念：`/var/lib/loom-device/state.json` 是保留 `v2_latch` 的 schema 3（见[现行编号](../core/current-contract.md#现行编号)）
`DeviceIdentity + CertifiedLKG` owner-only 原子文件，保留稳定身份、认证 floor 与完整 LKG；
`Preference` 随身份原子保存；`/var/lib/loom-device/runtime.json` 只保存当前底层网络代的有限
`Observation`，不保存第二份偏好或性能冷却状态；`/run/loom-client/config.json` 与 `status.json` 分别是可删除重建的
`RuntimeCandidate` 配置和 selector 回读投影。唯一正式 unit `loom-client.service` 运行
`loom client run`；access 数据面子进程必须先进入专用 network namespace，再启动精确签名包中的 sing-box、
应用共享纯核心给出的候选、逐项回读 selector，
再持续采集本机首跳并消费共享的链路和出口观测。真实业务观测保留原目标；WG 内部 DNS 与独立链路检查按各自范围单独回读。access 不执行候选乘网址的例行扫描。
重启保留原样本时间，并重新建立可删除的性能切换内存；持续采样按测量周期继续，不等样本过期。

TUN worker 在与 PID 1 或原 underlay 相同的 network namespace 中拒绝启动。监督进程保留原网络，
已验收的 Mixed/service unit 继续按原输入运行。隔离 TUN 的源码与正式 CLI 验证进展不代表生产验收完成；
实际安装、宿主不变量与崩溃恢复结果见[实施状态](../progress.md)。

#### 隔离 TUN 的执行边界

目标是让操作者显式启动的 Linux 应用使用现有 Service/Policy，且同机 control、转发、出网和管理连接保持
原 underlay。当前 Mixed 已满足显式代理应用，但普通 TUN 应用及其安装、停止恢复没有正式入口。最小变化
是由同一 `loom client run -capture tun` 监督独立 access 数据面进程，`loom client exec -- <command>`
是应用进入该边界的唯一产品入口；其他宿主进程不因安装而进入 TUN。新增操作成本是应用须从此入口启动。

认证 DeviceView、LKG、身份、Preference 与报告格式不变。唯一 agent 留在原网络处理私有配置、报告和已有
服务资源；同一认证 View 单向投影 access 与 server 执行配置。server listener/WG 继续在原网络，access
sing-box 与应用在本 generation 的匿名 network namespace。access 只含回环与自身 TUN，underlay socket
从固定的原网络 namespace 引用创建，不创建宿主 veth、地址、route/rule 或 firewall 对象。该引用只定位
本机执行环境，不授予任何候选或业务权限；数据面的 namespace 拨号适配须单独构建和真实验证，不能假定
当前固定的上游版本已有该能力。namespace 只是宿主执行输入，不能写入签名 View 或持久身份。

远端资源的拨号名称继续原样进入数据面，由同一 View 的认证解析器经 underlay DNS outbound 解析；
DNS 与传输 socket 都从固定的原网络引用创建。资源不需要在渲染时先变为字面 IP，也不向 access TUN
添加它的地址排除：排除并不提供原网络连接，而这里已经存在明确的 socket 隔离。没有认证解析器仍拒绝，
失败不借系统 DNS；原 CA、TLS 名称、凭据、候选及权限不变，重启从同一认证配置重新解析，不持久化答案。
最小验证是具名 Hy2 资源的隔离 TUN 实际 HTTPS、认证 DNS 查询、原身份重启和宿主网络回读；缺解析器
拒绝与运行投影不改变传输认证参数另有定向回归，不新增操作成本或权威字段。

namespace、进程句柄及本 generation 的运行文件都是执行资源，不能成为第二份权威或完成状态。父进程持有
内核引用，运行回读核对 access namespace 与原网络不同，且实际程序与配置匹配后才开放应用入口。应用
执行者在接收已核验的 namespace 引用后启动受监督的独立进程树；数据面和应用均核对独立 mount namespace，
将挂载传播设为私有并屏蔽宿主系统总线、networkd、解析服务和服务管理器的控制套接字。只有应用私有 mount namespace 设置业务
DNS；不修改宿主 resolver。服务停止、数据面异常或执行者退出都先终止相应应用树，再关闭 namespace 引用；
原应用不跨 generation 自动重启。正常停止、强制退出与启动中途失败均不得留下可继续绕过当前授权的应用。
应用树以独立 PID namespace 的 init 监督，执行者死亡由内核父死亡信号与固定父进程句柄共同覆盖；
service 使用经过核验的 pidfd 终止其精确进程树。握手释放前不执行用户命令，service 拒绝其他 UID
及不属于调用者的 PID namespace init；CLI 还核对服务端正在运行的精确 Loom 制品。应用执行前移除全部 capability，禁止通过 root exec 重新取得网络能力。
DNS 文件只是运行配置旁可重建的本代投影；传递只读文件引用，在应用私有 mount namespace 内核对 inode
后绑定，停止时比较所有权再删除。既不改写宿主 `/etc/resolv.conf`，也不保存新的 DNS 权威。
更新失败保留新 LKG，关闭不再符合授权的 access/server 执行；修复通道仍使用原 underlay。未知残留或清理
失败保持 failed/inactive，不自动反复施加。重启从原身份、LKG 和偏好创建新执行边界，不恢复旧 namespace。

反例：只把 sing-box 移进 namespace、让应用或 server listener 留在错误网络，分别会造成没有捕获应用或
破坏原服务；把 agent 整体移入 TUN 则可能递归捕获修复通道。验收须经正式安装/运行/exec 入口完成真实
DNS 与 HTTPS、授权收窄和恢复，并在正常停止、child/parent 强制退出、启动失败及重启后核对应用树和网络
清理。每次同时比较宿主 namespace、route/rule、resolver 文件及解析服务的逐接口 DNS/域/default-route，
并以新 SSH、LAN、WG、代理与公网连接验证原路径。
源码支持显式 `--capture tun` 生成同一 systemd unit，增加创建 namespace 所需的 `CAP_SYS_ADMIN` 和
`/dev/net/tun` 访问；Mixed 不增加这些权限。systemd 通过 `OpenFile` 预先打开 `/proc/1/ns/net` 并传入只读
文件描述符，供限权进程取得同一个初始 namespace 引用；worker 仍必须逐项比较
初始、underlay 和自身引用，不能因 `/proc` 读取被拒绝就跳过核对，也不为此授予 `CAP_SYS_PTRACE`。TUN 子进程门禁不因 unit 授权而放宽，纯服务节点不创建
access namespace。unit 沿已签模板与实际本机输入精确回读，升级可以显式切换 capture，但不回退发布代。
这些检查通过以前，不宣称对应部署完成。[系统总线事故](../incidents/2026-10-06-isolated-tun-host-dns.md)
说明为何仅比较网络空间或 resolver 文件不足以证明 DNS 隔离。

旧 CLI 的 `client policy select <ServiceID> <PolicyID>` 与按服务回读属于待迁移接口，不能作为
当前业务模型的选择前提。新入口应选择当前一条互联网 Policy，并回读它确定的 Service；
具体参数及偏好的前向替换未完成前，不用旧命令演示新目标已实现。
`loom client status` 只读取 `/run` 中的实际 Selection，不把偏好冒充为运行事实。service 启动时可以尝试
私有配置同步；控制面离线或报告暂不可达时继续使用已验证 LKG，不能改走公开配置或旧 pull。

设备把签名报告交给任一可达且已同步该设备授权事实的 control 即算上传成功。接收成员按当前
授权验证设备身份和原报告签名，当前结果另按签名 DeviceView 核对 `view_digest`；旧 View 只能保留为诊断。
成员通过控制成员私有认证通道交换[报告必要差量](../core/current-contract.md#control-成员之间的报告差量)，
补齐历史缺口和分叉证据；较旧的报告不能覆盖新结果。报告不参与治理权威，成员暂时不可达只会令该成员展示缺少观测；连通恢复后从
其他成员重新合并即可。签名报告将当前 `view_digest`、链路 Observation 的 `link_spec_digest` 和候选
Observation 所经链路的有序摘要一同纳入签名字节；接收方按当前 View 重算，不匹配时只投影 `unknown`，
不得沿用旧 `available`。客户端只在相关执行/探测输入经新旧 LKG 比对相同后，才可把旧观测留在新 View 的报告中；
无法证明相同时保守上报 `unknown`。
设备授权或 DeviceView 改变后，旧 `view_digest` 的报告即使签名正确也不得继续投影。

Linux 客户端制品同时为 amd64/arm64 生成、签名和逐文件验证。amd64 在原生宿主做业务验收；arm64
只交叉构建和静态检查。installer 先把精确制品放入内容标识 release 目录，并在切换 `current` 前对现有
LKG 执行 sing-box preflight；切换后若 service/selector 回读未成功，只有先前 release/unit 已证明不会在
初始 netns 接管宿主流量，且能消费当前已接受授权、不恢复已撤销权限时才可恢复运行；否则只恢复文件指针并保持 service disabled/failed。升级失败
不覆盖旧制品，也不得重新启用危险旧 unit。当前 installer 的失败路径尚需落实这一限制，见
[实施状态](../progress.md)。

installer 在停止任何既有 unit 前还必须检查现有 sing-box 入站的所有权。发现 Hysteria2、Trojan 或无法
证明属于本地客户端接管的入站时，客户端安装失败关闭；它不能把“新客户端自身可运行”解释为同机转发或出网
职责已被替代。相应数据面运行时只有在同一认证投影明确提供替代入站、报告和回读，并完成真实业务验收后才能
被退休。

### Windows profile 与 HostAdapter

Windows 的一个 profile 恰好绑定一组 `DeviceIdentity + CertifiedLKG + Preference`。这只是八概念在
本机的聚合保存，不是第九个网络领域实体。profile 索引只保存不透明本机 ID、显示名称、列表顺序、当前浏览行
和上次明确请求连接的 profile ID；最后一项只是重启时尝试恢复连接的本机用户意图，不是持久的 active 或
Selection。索引不保存设备公钥、floor、候选、当前连接、健康或 selector 值，删除后不能据此重建网络状态。
当前连接必须从正式 runtime 和 selector 回读；名称、顺序、浏览行和恢复请求都不能改变 Device、授权或
实际 Selection。

每个 profile 使用一个严格 schema 的 DPAPI envelope 原子保存 Ed25519 私钥及公钥绑定、稳定 claim request
ID、BootstrapCapability 约束、已验证 `ControlConfig` 成员链、已见事实前沿、不可回退 floor、`v2_latch=true`、
完整原始 `DeviceViewEnvelope` LKG 和唯一 Preference。Installed 使用 machine-scope DPAPI，并由 MSI 建立
SYSTEM/Administrators DACL；Portable TUN 与 Portable Mixed 使用 current-user DPAPI。磁盘上不得出现明文私钥、
拆出的运行配置、hydrate 后候选或第二份 LKG。写入使用同目录临时文件、落盘、原子替换和替换后独立回读；
任一步失败都保留旧 envelope。新 LKG 只有在 wire 规范、Ed25519 设备绑定、由当前信任绑定验证的
连续多数签名成员链、签发 control 的签名与事实前沿、稳定 View 内部约束和 floor 全部通过后，
才能与提升后的已验证成员链信任绑定、事实前沿及 floor 一起替换旧值；不能拼接新旧字段。
宿主 preflight、组件可用性及运行回读不决定认证 LKG 是否接受；应用失败遵循上述新认证配置规则，
保留新 LKG 并收口已撤销授权，不把旧 envelope 恢复为运行权威。

首次导入时先生成 Ed25519 身份并把 `authenticated_latch=true`、空 high_water、短邀请引用和待选意图原子
保护，再经受限 bootstrap tunnel claim/resume。同一事务恢复复用同一 identity/request ID；不同邀请不得接管。
完成后保存完整 LKG 并推进 floor。进程、SCM 服务或系统重启从同一 envelope 验证恢复；DPAPI 解密失败、schema
未知、latch 缺失、未经证书限定的前沿回退、LKG 无效或 Preference 非规范时整个 profile 失败关闭，不回退 P-256、公开配置、
旧 bundle 或 v1 路径。未完成事务不是可连接 profile，UI 只能显示可继续恢复的加入状态。

Windows HostAdapter 从 LKG 每次纯派生 `RouteCandidate` 与 `RuntimeCandidate`，启动签名包中的正式 sing-box，
先校验稳定 View 并派生资源 transport、来源 selector 与接收权限，再添加本机 API 输入；Windows capture 派生只添加一次
认证 DNS、Mixed/TUN 和 sniff 规则。独立 Hy2 首跳的地址、凭据、CA 与 TLS 名称必须原样保留；WG endpoint、精确来源绑定及执行 DNS 由同一认证投影提供，禁止 Hy2 detour；不能用仅接受
Direct 的平台校验器拒绝已经支持的认证候选，也不能重复添加 DNS 绕过该校验。平台结构校验不产生新授权，
未知字段、不安全 TLS、失效或循环 detour 与扩宽的 capture 仍须拒绝。派生值只随受监督子进程存在，停止后删除，
重启从原 LKG 重建；UI 与签名报告继续回读真实 selector，不从配置文件推定连接成功。
应用纯核心提出的候选后读取 Clash selector 的真实值。只有完整 Policy／默认／目标覆盖／入口出口值及自身 CAS 修订均读回确认时才形成
Selection；apply 成功但回读缺失、不一致或属于其他 Policy 时不更新 Selection。HTTPS 业务与独立传输检查的
成功或失败分别产生保留 action/scope 的真实 Observation；未单独执行的 UDP/DNS 保持未验证。本机 listener、自检、ICMP、
授权声明和 UI 颜色都不能产生 `available`。

已有认证 LKG 直接用于启动，不等待一次远端领取。配置沿既有私有等待接口连续跟随，通道失败时
独立退避；接受新 LKG 立即持久化，并取消仍使用旧运行输入的测量及报告 I/O，等待实际退出后由
原运行 owner 应用接收授权与来源选择的差量。签名报告独立发送，只保留一个待发送快照；旧 ACK
只有在调用对象、View 和包含网络代的运行事实全部仍匹配时，才确认当前报告。报告序列继续由
唯一受保护身份预留；队列和取消柄均是可丢弃运行值，不形成第二份状态或交付权威。

Installed、Portable TUN 与 Portable Mixed 只是 HostAdapter/交付差异：Installed 由 SCM 服务持有 machine DPAPI
和 TUN，Portable TUN 由提权前台进程持有 user DPAPI 和 TUN，Portable Mixed 只提供同一 runtime 的 mixed
入口且不改路由。三者消费同一个 profile envelope、候选派生、选择函数、selector 回读和报告 wire；不得各自
复制选路规则、候选 store 或健康状态机。源码、构建与制品判断只在 Linux 工作树；同机受限 VM 只做 x64 原生
执行，不能抵扣 ARM64、真实睡眠、物理网络切换和显示硬件终验。

Windows profile decoder 只接受现行 DPAPI envelope、Ed25519 身份及认证 LKG；P-256/证书旧状态不是
运行时输入，也不得以旧 bundle 或旧网络路径补足缺失字段。

## 最小必要测试集

测试验证模型边界，不枚举平台、受管节点、协议和故障的笛卡尔积。

1. **认证与恢复**：有效签名 LKG 可离线恢复；从已固定的 C0 成员表逐项验证后继表对前表的
   摘要引用、旧成员同一轮次多数签名、失格键封存序列，以及最终 View 签发者资格和设备绑定。
   缺少中间证明、任意新根、错误签名及未经证书限定的前沿回退均拒绝；封存低于已见高水位时，
   仅对该封存键允许证书限定的验收例外，原高水位和 latch 保留，旧 LKG 只在验收失败时保留；留任 control 在证书验收前已持久接受的超限撤权有原始
   证据时自动重签，证据缺失时标记可能复权且不伪称全部风险已被发现。失败不覆盖
   旧信任绑定、前沿、高水位或 LKG。没有派生中继段时仍可从设备认证私有入口领取配置，
   已有共享首跳可按授权使用。
2. **确定性派生**：相同 LKG＋Preference 在 Android/Linux/Windows 纯核心得到相同当前候选身份和顺序；相同平台
   能力值生成相同可执行集合，重启结果不变；能力不足时不改变授权候选 ID。
3. **Direct 与本地出网语义**：普通 Direct 的终点为 `direct`、链为空；设备限定本地出网终点为本机
   NodeID、链同样为空。两者身份不同，只能由所选 Policy 的完整规则决定允许哪一种；
   重建不丢失 NodeID，均不产生回拨本机的入口检查；一跳直达包含远端最终出口，不与二者混淆。
4. **同出口多路径**：同一最终出口同时产生一跳直达和中继；不同 WG/Hy2 首跳资源及自动 WG
   中继段的 `LinkID` 分别形成候选 ID，资源可按 ID 复用；关闭
   `public_data_ingress` 只删除引用该入口的一跳候选，其他共享资源首跳仍保留；开启它不会自动得到
   `available`；hybrid access 在出口无
   公网入口时仍可通过自己已认证且平台支持的 link 形成候选，不生成本机回环 inbound 凭据。
5. **三态观测**：真实成功、真实失败、缺失/过期/跨网络代分别得到 available、unavailable、unknown；
   WG 与 Hy2 首跳及共享同一 peer 的自动 WG 正反段都只按各自资源或 LinkID 的真实结果改变状态，未实测者
   保持 unknown；同 ID 链路或资源更新规范内容后，旧 `link_spec_digest` 的链路/候选观测及签名报告失效，
   不影响未引用该资源的候选；ICMP 成败只改变 RTT 提示，不改变三态。
6. **非阻塞与 fallback**：启动在观测未完成时即可应用合法候选；Android 在验证并持久保存
   `CertifiedLKG` 后，VPN/selector 回读可使 profile 成为 active，缺少获授权业务目标仍为 `unknown`；
   真实业务失败更新观测并
   选择同一最终出口的必要中继 fallback，后续成功可恢复，无需配置变化或删除认证 LKG。
7. **运行事实**：adapter apply 成功但 readback 不匹配时不更新 Selection；UI 显示回读实际值，
   不把 Preference 显示为当前路径。
8. **平台契约**：Android/Linux/Windows adapter 各用一个成功 outcome、一个失败 outcome、一次 apply/readback
   验证接口；真实验收各选一条可工作的正常路径和一条同出口 fallback 即可。
9. **认证与运行应用分离**：稳定 View 不含候选或运行 JSON；未知／非规范字段、内部授权不自洽
   使新 View 认证失败。运行投影损坏不得反向拒绝已原子接受的授权；即使宿主 preflight、组件或
   启动失败也保留新 LKG/floor；仅允许仍符合新授权的旧执行，已撤销服务不得因其他资源失败恢复。
   重启后继续以新 LKG 修复，UI 分别显示认证配置和实际应用结果。
10. **Windows DPAPI 与 profile 隔离**：machine/user scope 不能互换；每个 profile 的 Ed25519 身份、floor、
    latch、完整 LKG 与 Preference 往返相等，原子替换失败保留旧值；索引损坏不能制造或覆盖网络权威。
11. **Windows 严格 wire 与恢复**：稳定 View 中含旧 RuntimeProfile／routes、未知／缺失字段、重复键或
    非规范 JSON 均拒绝；重启从同一 DPAPI LKG＋Preference 重建，Selection 仍只来自完整 readback。
12. **Windows 最小原生闭环**：Installed x64 用一个 profile 完成 UI invite → claim/resume → DPAPI → runtime →
    selector readback → 原域名 HTTPS 与独立链路检查 → 一个 unavailable 候选 → 同出口 fallback → 签名 report/readback；再按同一
    adapter 契约抽样 Portable TUN/Mixed 的 capture、清理和持久差异，不建立 Edition × 模式 × 协议矩阵。
13. **共享业务探测**：网址直接来自当前 Policy 所属 Service；限制开关关闭时允许普通互联网，开启时才限制到声明目标；
    相同出口／URL／请求及解析参数仅测一次，来源证据跨设备／Service／Policy 复用，权限仍各自校验。空投影只使相应业务
    范围保持 unknown，不扩大 ACL、不阻断加入；中继链路的精确目标按 `LinkID` 独立验证。
14. **Linux capture 隔离**：初始 network namespace 的 TUN worker 失败关闭；监督进程只能创建专用
    namespace 中只捕获显式 workload；同机 control + forward + internet_egress 在没有 TUN 时保持业务可用；正常
    停止、child/parent crash、SIGKILL、启动中途失败和重启后，宿主 rule、main route、LAN、WireGuard、DNS、
    代理与 SSH 回读均保持基线，未知所有权对象不会被删除。
15. **DNS 与局域网**：`.loom` 仅精确 A/AAAA、`control.loom` 保留，解析不扩大 ACL；
    选择了 mapping Service 所属有效 allow Policy 的 access 才得到虚拟前缀及固定网关候选，撤权后精确路由和 DNS 投影消失。
    映射范围没有适用 HTTPS 目标时保持 unknown，真实业务结果只证明所访问目标；互联网 Preference 不受影响。

16. **策略分配与范围**：同服务可授多条 Policy，可选集合中重复 PolicyID 拒绝；未分配和 deny 均无业务权限；any 只枚举实际合格资源；
    only 的唯一出口删除后无替代受管出口；none 不等于 any；关闭 Direct 的指定出口规则不能直连绕过；
    LAN 终点不可替换。策略变更仅使依赖其规范摘要的观测失效，重启从认证 LKG 恢复相同范围。

扩展测试只能在上述最小集合通过后进行，并且发现新场景时优先把它表达为新的候选或观测数据，
而不是新增路由分支。

## 明确禁止

- 不整套搬回旧 scheduler、registry 或与目标无关的预热状态机。用户已要求的节点统一预算、
  持续测量、必要备选探索及持续改善判定须按当前模型实现，不能因旧组件名称相似而禁止必要能力。
- 不按 Service × 候选路径做完整业务扫描，不要求所有出口和所有 transport 都实测一遍。
- 不为未知状态补样本，不用 ICMP 或单段 RTT 伪造端到端健康与 P50/P95。
- 不把 `public_data_ingress`、认证配置或服务端声明解释为当前可用。
- 不因一跳直达存在而删除同出口中继，也不恢复 direction/reverse_only 配置来排除合法资源。
- 不合并使用 WG/Hy2 不同首跳的候选；自动 WG 正反段独立观测，不借另一传输的观测补绿。
- 不因 `LinkID`、资源 ID 或候选 ID 相同就沿用旧观测；`link_spec_digest` 不匹配时相关选择与报告重算。
- 不从节点字段、硬编码域名或探测结果构造权限；网址由 Service 声明，访问边界由明确限制开关与 Policy 决定，
  缺少获授权目标保持业务 unknown。
- 不把 Android/Linux/Windows 平台差异写进纯选择规则；Windows Edition 差异只进入 HostAdapter。
- 不持久化派生候选或期望选择来绕过重建与 selector readback。
- 不新增与上述概念重复的 manager、store、ledger、gate、phase 或 receipt；持续测量复用节点的
  正式运行循环与统一预算，不因旧文档禁止后台循环而停止用户要求的持续优化。
- 不让 profile 索引、显示名称、UI 选中行、SCM 状态或本机 listener 成为第二网络权威。
- 不读取旧配置 overlay、旧 bundle、P-256/证书状态或旧网络路径作为运行 fallback。
- 不用旧 capability 或任意新信任根读取设备配置；无链路时的现行 device-authenticated 私有入口
  不能把业务或链路状态补成 available。
- 不在开发宿主初始 network namespace 运行 access TUN，不用 endpoint 排除、`auto_detect_interface`、临时主机
  路由或业务成功掩盖缺失的 capture 隔离与 rollback。

## Android 的业务观测展示

目标是沿现有连接页和诊断页回读每个已授权 Service、实际 HTTPS 目标、来源候选、原采样时间和
有效期；候选及 selector 的回读时间单列。业务失败、过期或没有样本不能改变 VPN 的真实连接状态，
一个 Service 的成功也不能代表其他目标。现有私有报告及受保护观测缓存已有这些原值，但 Android
UI 只得到汇总文字及当前路径，没有完整来源和有效期；失败后候选退出选择时还会丢失可见的失败依据。

最小变化只增加一个可删除重建的 UI 值 RouteBusinessStatus，从原 ManagedProfile 的授权候选、
Service 探测目标、当前 selector 回读、原观测缓存及调用方注入的时间投影。它没有独立身份、存储、
wire 或完成状态。domain、规范签名、持久原件、选路算法、VPN 及报告行为均不变；Compose 只消费
此投影，不能由汇总字符串反推结果、改写样本或赋权，也不新增操作者步骤。Activity 按原有效期
注入展示时间并在到期时重绘，纯 Compose 与截图使用固定输入；时间不会倒写原样本或触发业务选择。

每个当前授权的 Service/目标保留一项展示；有当前选择时优先对应候选的唯一样本，否则仅展示该
目标最新的仍获授权候选的历史依据。来源候选、网络代、Service、目标及动作必须相符；缺失、歧义、
撤权、其他目标或网络代的材料不产生当前结果。只有运行中、与当前选择一致且在原有效期内的样本
才能标为当前；其他原值明确为历史，原采样时间、有效期和实际结果仍保留。无样本显示未知，
没有当前选择时不能以旧候选成功宣称业务可用。同一来源同刻异值不择一制造成功。

反例：Service A 的目标成功而 B 的目标失败并退出选择，VPN 仍运行；A 与 B 分别展示自己的原观测，
B 的历史失败依据保留，但不假称仍选中了该候选；没有样本的目标继续未知。最小验证覆盖该正常/失败
对照、目标/网络/候选绑定、过期/停止/撤权及原时间的缓存读回，随后由 Compose 和模拟器正常入口
回读实际业务与原签名报告；未改平台复用原件，不重复完整传输矩阵。旧汇总“业务 DNS/HTTPS”
作为业务结果依据的显示路径由此替换；原 report 和调试信息不建立第二权威。

展示不改变既有业务缓存的清除规则：正常停止、认证配置替换和网络代变化已经清除的样本不会在
重启后被 UI 恢复或补造。仍存在的原缓存可按相同绑定重建投影；没有原件时显示未知。

## Windows 的业务观测与原生页面

目标是正常原生页面逐 Service、实际目标、候选和网络范围展示业务原时间/有效期，与 selector 回读
完成时间分开；失败服务退出选择后保留它自己的原依据，其他服务继续运行。修订前运行状态已有原
Observation，但展开 UI 缺有效期，且把最新业务采样当成 selector 读取时间，属于显示接线缺口。

最小修订延续 windowsPathDisplay：原临时 windowsRuntimeStatus 的 Selections/BlockedScopes 与
认证 View 决定服务行，Observations 只按授权候选、Service、目标、动作及网络代投影业务说明文本。
有选择时采用该候选的唯一样本；拒绝服务仅展示最新仍获授权来源的历史依据，同刻异值、缺失、
过期、未来及其他网络不能制造当前成功。所有原时间与结果保留，不从说明字符串反推状态。
Windows 调用方在真实 ActivateServices 完成后立即注入 selector_read_at，沿既有可删除状态文件
送到同一 UI；上报等待或 UI 轮询不会改写它。该临时值不进入签名事实、报告、DPAPI、floor 或
共享选路算法，旧临时文件可删除重建，缺时间显示未知，不能借业务时间补值。

domain、wire、persistent 均不变；runtime 仍为原状态文件，UI 仅增加可删除的说明与回读时间，
原生绘制使用现有 DirectWrite 度量并按内容增高。布局遵循[已确定原型](prototype-review.md#目标布局与线条)：
同一窗口、侧栏和滚动视口，画布、完整面板、32 DIP 控件与服务内展开说明不改变功能入口或拥有权。
首次空态没有设备身份/删除/当前连接，添加后仍须正常加入并保存才有列表条目；不新增配置或操作步骤。

最小验证覆盖 A 的两个实际成功目标、B 的失败依据、无样本/过期/错误绑定/同刻歧义与原时间；
同机 VM 通过真实 UI/报告/DPAPI 重启回读，原生首次空态、展开及滚动、键盘和必要 DPI 交互继续使用
生产控件验证。正式六款应用包与原 manifest 发布/下载，未改平台复用原件；物理 ARM64、网络切换、
睡眠和显示硬件仍由用户终验。禁止恢复旧页面状态机、重复身份或旧协议入口。
